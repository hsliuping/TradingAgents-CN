# Cherry-pick 矩阵

定义 Bug 修复从一个版本线同步到其他版本线的规则。

## 规则

| Bug 所在版本线 | 自动 Cherry-pick 目标 | 说明 |
|---------------|----------------------|------|
| 2.0.x | `release/2.0.x` | 仅影响 2.0.x，不同步到更高版本 |
| 2.1.x | `release/2.1.x` → `main` | 修复需同步到 v3.0 开发主线 |
| 3.0.x / main | `release/2.1.x` → `release/2.0.x` | 需判断 Bug 是否存在于旧版本 |

## 判断原则

1. **向上同步**：低版本（2.0.x）的修复一般不需要同步到高版本（2.1.x/3.0），除非确认同一 Bug 存在
2. **向下同步**：高版本（main/3.0.x）的修复应 cherry-pick 到活跃的 release 分支
3. **冲突处理**：如果 cherry-pick 冲突，不强制合并，提示用户手动解决
4. **数据库兼容**：补丁版本的修复不应包含数据库结构变更，确保 cherry-pick 后不会破坏旧版本
