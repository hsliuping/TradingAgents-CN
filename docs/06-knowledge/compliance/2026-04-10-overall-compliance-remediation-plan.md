# 整体合规整改方案（2026-04-10）

## 1. 文档目的

本文用于固化当前版本的整体合规整改方案，作为后续代码整改、复核验收、上线评审和回归检查的统一依据。

本文重点解决的问题不是“表述是否更委婉”，而是系统当前仍存在从研究分析走向交易建议、仓位建议和执行建议的链路风险。整改目标是将产品整体定位收敛为：

1. 研究辅助与学习型产品。
2. 用户自定义规则提醒与复盘辅助产品。
3. 不提供个股买卖、仓位配置、止盈止损和交易计划建议的产品。

---

## 2. 适用范围

本方案适用于以下功能与模块：

1. 单股分析工作流。
2. 持仓分析与持仓报告。
3. 股票关注列表定时分析与通知。
4. 交易员、最终决策、风险管理决策等 Agent 输出。
5. 报告聚合、推荐摘要、邮件导出、附件导出。
6. 用户交易计划与止盈止损提醒。

---

## 3. 当前风险判断

### 3.1 当前主要风险不是免责声明不足

当前系统已有部分免责声明和“合规术语替换”逻辑，但这不足以消除风险。只要系统仍然对具体证券输出以下内容，就仍存在明显的非法荐股或变相投资咨询嫌疑：

1. 买入、卖出、持有、加仓、减仓、清仓等方向性结论。
2. 目标价、建仓价、止盈价、止损价、支撑位、压力位等具体价位。
3. 仓位比例、建议金额、建议数量、风险敞口等配置建议。
4. 分批建仓、退出条件、执行条件、胜率、期望收益、风险收益比等交易计划。

### 3.2 当前主要问题是“交易建议链路仍然存在”

当前版本的高风险链路主要体现在：

1. 工作流注册层仍把“交易员制定策略”“持仓操作建议师”作为正式能力。
2. 聚合层仍从 `trader_investment_plan`、`final_trade_decision` 等字段提取推荐摘要。
3. 持仓分析仍直接要求输出操作建议、止盈止损、建议数量和建议金额。
4. 股票关注列表定时分析仍对外汇总 recommendation，并统计买入、卖出、持有数量。
5. 现有部分“合规化”处理只是将“买入/卖出/持有”替换为“看涨/看跌/中性”，但源头的交易建议并未删除。

### 3.3 当前整改原则

本次整改不采用“仅靠术语替换”的方案，而采用“源头去交易建议化”的方案。

---

## 4. 合规红线

以下能力和输出，原则上不得再对用户开放：

1. 对具体股票给出买入、卖出、持有、加仓、减仓、清仓结论。
2. 给出目标价、止盈价、止损价、建仓区间、突破价、跌破价。
3. 给出建议仓位、风险敞口、建议数量、建议金额。
4. 生成“最终交易决策”“交易计划”“投资建议”“操作建议”等用户可见结果。
5. 结合用户真实持仓、成本价、总资金、风险偏好，输出下一步该如何操作。

以下能力可以保留，但必须限制为非建议型输出：

1. 大盘分析、基本面分析、新闻分析、情绪分析、行业分析。
2. 风险揭示、数据缺口、争议点、情景分析。
3. 用户自定义交易规则的到价提醒、条件触发提醒。
4. 交易复盘、纪律复盘、计划一致性检查。

---

## 5. 整改总目标

整体整改目标分为三句话：

1. 保留研究，移除决策。
2. 保留提醒，移除建议。
3. 保留复盘，移除代客判断。

整改完成后，系统对外应只输出以下类型内容：

1. 事实摘要。
2. 证据对照。
3. 风险因素。
4. 待验证指标。
5. 情景分析。
6. 用户自定义规则触发提醒。

---

## 6. 分阶段整改方案

### 6.1 第一阶段：立即止血（P0）

目标：在最短时间内切断最危险的对外输出链路。

#### P0-1 下线交易员对外输出

执行内容：

1. 停止对外暴露 `trader_investment_plan`。
2. 停止对外暴露 `investment_plan` 中的交易计划性质内容。
3. 停止对外暴露 `final_trade_decision`。
4. 聚合层不再从上述字段生成 `recommendation`。

重点文件：

1. [app/services/workflow_registry.py](../../app/services/workflow_registry.py)
2. [app/routers/workflows.py](../../app/routers/workflows.py)
3. [app/services/task_analysis_service.py](../../app/services/task_analysis_service.py)
4. [app/services/simple_analysis_service.py](../../app/services/simple_analysis_service.py)

#### P0-2 暂停持仓分析中的操作建议输出

执行内容：

1. 移除 `action`、`stop_loss_price`、`take_profit_price`、`suggested_quantity`、`suggested_amount`。
2. 停止使用“加仓/减仓/持有/清仓”作为最终输出。
3. 对外仅保留持仓诊断、风险揭示、数据缺口和情景分析。

重点文件：

1. [app/services/portfolio_service.py](../../app/services/portfolio_service.py)
2. [app/models/portfolio.py](../../app/models/portfolio.py)
3. [app/routers/portfolio.py](../../app/routers/portfolio.py)
4. [app/services/workflow_registry.py](../../app/services/workflow_registry.py)

#### P0-3 停止股票关注列表定时分析中的推荐汇总

执行内容：

1. 删除 recommendation 汇总。
2. 删除买入、持有、卖出统计。
3. 邮件和附件仅保留“观察摘要”“重点变化”“风险提示”。

重点文件：

1. [app/worker/watchlist_analysis_task.py](../../app/worker/watchlist_analysis_task.py)
2. [app/services/email_service.py](../../app/services/email_service.py)

#### P0-4 禁止“表面合规化继续透出交易建议”

执行内容：

1. 停止使用“买入 -> 看涨、卖出 -> 看跌、持有 -> 中性”的替换逻辑作为最终整改手段。
2. 对已经命中交易建议语义的内容，直接截断或改为研究型摘要，不做术语包装后透出。

重点文件：

1. [app/routers/analysis.py](../../app/routers/analysis.py)

### 6.2 第二阶段：结构整改（P1）

目标：从角色、数据结构和输出口径上完成“去交易建议化”。

#### P1-1 重构角色体系

保留：

1. 大盘分析师。
2. 基本面分析师。
3. 新闻分析师。
4. 情绪分析师。
5. 研究经理。
6. 风险揭示角色。

删除或改造：

1. 交易员。
2. 持仓操作建议师。
3. 最终交易决策角色。

改造方向：

1. 交易员改为“研究整合员”或“证据审阅员”。
2. 只负责归纳争议点、证据缺口、待验证指标。
3. 不再输出交易计划、仓位方案、价位方案。

#### P1-2 重构单股分析输出结构

允许字段：

1. `summary`
2. `evidence`
3. `risks`
4. `data_gaps`
5. `scenarios`
6. `watch_items`
7. `information_sufficiency`

禁止字段：

1. `recommendation`
2. `action`
3. `target_price`
4. `price_analysis_range`（如仍用于价格建议语境）
5. `position_ratio`
6. `stop_loss`
7. `take_profit`
8. `expected_return`
9. `win_rate`

#### P1-3 重构持仓分析为“持仓体检/持仓风险诊断”

保留：

1. 集中度。
2. 行业暴露。
3. 估值敏感性。
4. 财报与事件风险。
5. 技术状态描述。
6. 风险暴露与信息缺口。

删除：

1. 所有操作动作结论。
2. 所有止盈止损输出。
3. 所有建议仓位、建议数量和建议金额。
4. 所有与“目标收益率对应动作”相关内容。

#### P1-4 保留交易计划，但限定为“用户规则管理”

允许：

1. 用户录入自己的计划。
2. 系统检查计划完整性和一致性。
3. 根据用户预设规则做提醒。
4. 复盘是否遵守用户自己的计划。

禁止：

1. AI 为某只股票生成计划。
2. AI 依据个股分析替用户补全可执行交易规则。
3. AI 输出更合理的止盈止损价或建仓方案。

### 6.3 第三阶段：治理与防回归（P2）

目标：建立统一的合规输出网关，避免后续功能回归。

#### P2-1 建立统一输出合规过滤器

所有用户可见输出，包括接口返回、报告详情、导出文件、邮件、异步任务通知，统一经过一层合规过滤。

过滤范围至少包括：

1. 买卖动作词。
2. 仓位词。
3. 价位词。
4. 止盈止损词。
5. 风险收益和胜率词。
6. 执行条件和交易计划词。

#### P2-2 建立字段级白名单

原则：不是替换关键词，而是只允许白名单字段对外透出。

#### P2-3 导出链路与通知链路纳入同一规则

要求：导出器、邮件模板、异步通知不允许绕过主接口的合规规则。

#### P2-4 增加上线前合规检查项

要求：新功能上线前必须回答以下问题：

1. 是否输出了具体证券的操作结论。
2. 是否输出了具体价位或仓位。
3. 是否结合用户持仓或总资金生成建议。
4. 是否通过导出、邮件、附件侧路透出交易建议。

## 8. 验收标准

整改完成后，任意单股分析、持仓分析、股票关注列表摘要、邮件通知、导出报告中，都不应再出现以下内容：

1. 买入、卖出、持有、加仓、减仓、清仓。
2. 目标价、止盈价、止损价、建仓价、支撑位、压力位对应动作。
3. 风险敞口、建议仓位、建议数量、建议金额。
4. 最终交易决策、交易计划、投资建议、操作建议。
5. 胜率、期望收益、风险收益比、执行条件、分批建仓方案。

整改完成后，对外应只保留：

1. 事实摘要。
2. 风险提示。
3. 证据对照。
4. 分歧点。
5. 数据缺口。
6. 用户自定义规则提醒。

## 11. 建议执行顺序

建议按以下顺序推进：

1. 切断交易员输出链路。
2. 将持仓分析改造成持仓体检/风险诊断。
3. 将股票关注列表定时分析改造成观察摘要。
4. 增加统一合规过滤层。
5. 最后补齐测试、导出、通知与文档同步。

---

## 12. 结论

本次整改不应理解为“加强免责声明”或“优化前端文案”，而应理解为一次产品能力边界重划。

真正需要完成的是：

1. 从源头删除交易建议能力。
2. 从结构上重塑输出模型。
3. 从治理上建立统一防回归机制。

整改完成后，系统应明确稳定在“研究辅助、风险揭示、规则提醒、复盘支持”的合规边界内。
