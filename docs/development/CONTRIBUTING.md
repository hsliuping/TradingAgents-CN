> **贡献者许可协议**

> 2. 项目所有者可以以任何协议（包括商业许可）重新分发
> 3. 您保留对贡献代码的个人使用权

> 5. 您理解本项目采用混合许可证模式，部分代码为专有代码

首次提交 PR 时，请在 PR 描述中添加：`I have read and agree to the CLA.`

## 🏆 贡献者等级与回报

我们为贡献者提供清晰的成长路径，贡献越多回报越多。

### 等级体系

```
Level 1：社区用户
  │  提 Issue、测试反馈
  ↓  签署 CLA，提交第一个 PR
Level 2：贡献者（Contributor）
  │  在开源版上贡献代码
  │  合并 1+ PR → Pro 版 3 个月授权
  │  合并 3+ PR → Pro 版 1 年授权
  ↓  持续贡献 3 个月，质量稳定
Level 3：核心贡献者（Core Contributor）
  │  签署 NDA，获得 Pro 版私有仓库访问权限
  │  参与 Pro 版开发
  │  永久授权 + 收入分成（5-10%）
  ↓  合作 6 个月以上，贡献突出
Level 4：团队成员（Team Member）
  │  参与核心开发 + 架构决策
  │  收入分成（10-20%）
  │  可作为项目对外代表
```

### 各等级权限

| 权限 | Level 2 | Level 3 | Level 4 |
|------|---------|---------|---------|
| 开源仓库写权限 | ✅ | ✅ | ✅ |
| Pro 版授权 | 限期 | 永久 | 永久 |
| Pro 版私有仓库访问 | ❌ | ✅ 指定模块 | ✅ 完整 |
| 参与开发讨论 | ❌ | ✅ | ✅ |
| 架构决策 | ❌ | ❌ | ✅ |
| 收入分成 | ❌ | 5-10% | 10-20% |

### 晋升标准（Level 2 → Level 3）

| 维度 | 考察点 | 达标标准 |
|------|--------|---------|
| 代码质量 | PR 是否需要反复修改 | 多数 PR 一次通过或小修 |
| 技术能力 | 是否能独立解决复杂问题 | 至少 1 个中等难度 Issue |
| 持续性 | 是否稳定投入 | 3 个月内至少 5 个合并 PR |
| 沟通协作 | Issue/PR 讨论是否专业 | 有效沟通，不情绪化 |

## 🤝 如何贡献

### 1. 报告问题
- 使用 GitHub Issues 报告 Bug
- 提供详细的问题描述和复现步骤
- 包含系统环境信息

### 2. 功能建议
- 在 GitHub Issues 中提出功能请求
- 详细描述功能需求和使用场景
- 讨论实现方案

### 3. 代码贡献
1. Fork 项目仓库
2. 创建功能分支 (`git checkout -b feature/amazing-feature`)
3. 提交更改 (`git commit -m 'Add some amazing feature'`)
4. 推送到分支 (`git push origin feature/amazing-feature`)
5. 创建 Pull Request
6. 在 PR 描述中确认 CLA

### 4. 文档贡献
- 改进现有文档
- 添加使用示例
- 翻译文档
- 修正错误

## 📋 开发规范

### 代码风格
- Python：遵循 PEP 8 规范
- Vue/TypeScript：遵循项目 ESLint 配置
- 使用有意义的变量和函数名
- 添加适当的注释和文档字符串
- 保持代码简洁和可读性

### 提交规范

使用 Conventional Commits 格式：
```
feat: 新功能描述
fix: Bug修复描述
docs: 文档变更
refactor: 重构描述
chore: 构建/工具/依赖变更
perf: 性能优化
test: 测试相关
```

### 测试要求
- 为新功能添加测试用例
- 确保所有测试通过
- 保持测试覆盖率

## 🔧 开发环境设置

### 1. 克隆仓库
```bash
git clone https://github.com/hsliuping/TradingAgents-CN.git
cd TradingAgents-CN
```

### 2. 创建虚拟环境
```bash
python -m venv env
source env/bin/activate  # Linux/macOS
# 或
env\Scripts\activate  # Windows
```

### 3. 安装依赖
```bash
pip install -r requirements.txt
```

### 4. 配置环境变量
```bash
cp .env.example .env
# 编辑 .env 文件，添加必要的 API 密钥
```

### 5. 运行测试
```bash
python -m pytest tests/
```

## 💰 收入分成机制

核心贡献者及以上等级可参与收入分成：

### 分配方式

```
每季度收入分配：
  - 30% → 项目所有者
  - 35% → 团队奖金池（按贡献点数分配）
  - 17.5% → 开源社区基金（bounty、服务器费用）
  - 17.5% → 再投资（营销、法务、工具）
```

### 贡献点数

| 贡献类型 | 点数 |
|----------|------|
| 每个 PR | +1 点 |
| 每个 bug 修复 | +0.5 点 |
| 重大功能 | +5 点 |
| 文档完善 | +0.5 点 |

季度末按点数比例分配奖金池。
