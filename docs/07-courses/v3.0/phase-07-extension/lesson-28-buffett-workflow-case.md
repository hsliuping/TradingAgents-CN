# 第 28 课:巴菲特工作流实战——端到端造一个

> **课时**: 60 分钟(建议分 2-3 次完成) | **难度**: ⭐⭐⭐ 进阶 | **前置**: 第 26-27 课

> ⚠️ **风险提示**:本课程以"巴菲特工作流"为案例演示平台能力,工作流输出的所有内容(内在价值、护城河评分、安全边际等)**仅供研究参考**,不构成投资建议。A 股市场与美股市场结构性差异较大,巴菲特方法论的直接应用需谨慎,所有投资决策由用户自行判断,盈亏自负。

## 🎯 学完后能做什么

- 从**0 到 1** 端到端造一个完整的"巴菲特工作流"
- 掌握**4 阶段**实施法:需求 → 数据 → Agent → 工作流
- 理解**3 层架构**:Skill(数据) → Agent(分析) → Workflow(编排)
- 掌握**5 个 Agent** 的设计思路与提示词工程
- 学会**系统化调试**方法,而不是瞎调
- 能在**多个场景**复用工作流(单股/批量/持仓/行业)

## 🤔 多角度思考:为什么需要"工作流"?

### 角度 1:从巴菲特本人看——他是怎么研究的?

巴菲特分析一只股票,平均要读 **500-1000 页**资料(年报、季报、行业报告、管理层访谈)。**普通人做不到**:
- 时间精力有限(每只 500 页? 10 只就是 5000 页)
- 知识盲区(很多行业看不懂)
- 主观偏差(容易"爱上"自己持仓的股票)

**工作流 = 把巴菲特的研究方法论"标准化、自动化"**,让 AI 帮他做第一遍筛选,人做最终判断。

### 角度 2:从工程角度看——为什么分层?

```
┌──────────────────────────────────────┐
│  Layer 3: Workflow(工作流)            │  ← 怎么编排
│  节点 + 连接 + 顺序 + 条件            │
├──────────────────────────────────────┤
│  Layer 2: Agent(分析师)              │  ← 怎么分析
│  提示词 + 角色 + 输入输出             │
├──────────────────────────────────────┤
│  Layer 1: Skill(数据源)              │  ← 数据从哪来
│  Tushare / AKShare / 公告 / 新闻     │
└──────────────────────────────────────┘
```

**分层的好处**:
- **可复用**:同一个 Agent 可用于多个工作流
- **可调试**:每层独立测试,问题定位快
- **可扩展**:新数据源加 Skill,新分析方法加 Agent
- **可协作**:不同人开发不同层

### 角度 3:从用户使用角度看——和"直接让 AI 写报告"有什么区别?

| 方式 | 输出 | 可调试 | 可复用 | 一致性 |
|------|------|--------|--------|--------|
| **直接问 AI** | 每次输出都不一样 | ❌ | ❌ | 低 |
| **工作流** | 标准化结构化输出 | ✅ | ✅ | 高 |

**类比**:工作流 = **"菜谱"**,AI 自由发挥 = "看心情炒菜"。菜谱保证每次出品质量稳定。

## 📊 巴菲特工作流全景图

### 投资哲学 4 支柱 → 5 个 Agent → 3 个阶段

| 巴菲特理念 | 对应 Agent | 工作流阶段 |
|----------|----------|----------|
| 内在价值 | **内在价值评估师** | 阶段 1:基础分析 |
| 持久竞争优势 | **护城河分析师** | 阶段 1:基础分析 |
| 优秀管理层 | **管理层评估师** | 阶段 1:基础分析 |
| 安全边际 | **安全边际分析师** | 阶段 2:综合判断 |
| 综合决策 | **综合决策师** | 阶段 3:最终输出 |

> 💡 **设计原则**:每个 Agent **单一职责**,不互相重叠,确保输出可验证。

### 工作流的"3 阶段执行顺序"

```
阶段 1 (可并行):
  ┌─ 内在价值评估师 ─┐
  ├─ 护城河分析师 ────┼─ → 输出:3 个独立评分
  └─ 管理层评估师 ──┘

阶段 2 (依赖阶段 1):
  └─ 安全边际分析师 → 输出:安全边际 + 买入区间

阶段 3 (依赖阶段 2):
  └─ 综合决策师 → 输出:决策标签(乐观/审慎/中性)+ 评估结论
```

**为什么这样排?**
- 阶段 1 三个分析**互不依赖**,并行最快(5 分钟 → 2 分钟)
- 阶段 2 需要阶段 1 的数据,串行
- 阶段 3 综合所有输出,最后

## 🖱️ 端到端操作(分 4 阶段)

### 阶段 1:需求定义(10 分钟)

#### 1.1 写需求文档模板

任何工作流前,先写需求文档。模板:

```markdown
## {工作流名称}

### 目标(Why)
- {这个工作流要解决什么问题}
- {适用场景:单股/批量/持仓/行业}

### 输入(What)
- 必填: {股票代码 / 行业名称 / ...}
- 选填: {分析深度 / 时间范围 / 行业对比}

### 流程(How)
- 阶段 1: {基础分析}
- 阶段 2: {综合判断}
- 阶段 3: {最终输出}

### 输出(So what)
- {字段 1}: {类型/单位/含义}
- {字段 2}: {类型/单位/含义}
- {决策标签}: {枚举值}

### 约束(Constraints)
- 平台: {A 股 / ETF}
- 响应时间: {< 10 分钟}
- 失败处理: {失败重试 1 次}
```

#### 1.2 实战:巴菲特工作流需求文档

```markdown
## 巴菲特价值投资工作流

### 目标
按巴菲特价值投资方法论评估 A 股,识别"价格低于内在价值 + 有护城河 + 好管理层"的标的。

适用场景:中长线选股 / 持仓研究 / 行业对比

### 输入
- 必填: 股票代码(如 600519)
- 选填: 行业(用于行业对比,默认"未知")

### 流程
1. 阶段 1(并行): 内在价值评估 + 护城河评估 + 管理层评估
2. 阶段 2(串行): 安全边际分析(基于阶段 1 输出)
3. 阶段 3(串行): 综合决策(基于阶段 2 输出)

### 输出
- 内在价值估算(元/股): float
- 护城河评分(0-5): int
- 管理层评分(0-5): int
- 安全边际(%): float
- 决策标签: 乐观 / 审慎 / 中性
- 评估结论: string(200-500 字推理)
- 投资调整建议: string(基于研究结论的非强制性建议)

### 约束
- 平台: 仅 A 股和 ETF
- 响应时间: < 10 分钟
- 失败处理: 单 Agent 失败不阻塞整个工作流
```

### 阶段 2:数据源(Skill)准备(15 分钟)

#### 2.1 检查现有 Skill 是否够用

进入「分析流」→「Skill 中心」,看系统内置 Skill 列表。**巴菲特工作流需要的核心数据**:

| 数据 | 现有 Skill | 状态 | 处理方式 |
|------|----------|------|---------|
| 财务数据(年报/季报) | `tushare_financial` | ✅ 内置 | 直接用 |
| 实时行情 | `market_data` | ✅ 内置 | 直接用 |
| 行业数据 | `industry_classification` | ✅ 内置 | 直接用 |
| 公司公告 | `announcement_fetcher` | ✅ 内置 | 直接用 |
| 新闻舆情 | `news_sentiment` | ✅ 内置 | 直接用 |
| 管理层访谈 | ❌ 无 | 缺失 | 跳到 2.2 自建 |
| 同业对比 | ❌ 无 | 缺失 | 跳到 2.2 自建 |

#### 2.2 创建自定义 Skill(示例:管理层信息 Skill)

**进入「分析流」→「Skill 中心」→ 点"创建 Skill" → 选"API Skill"**

```yaml
# 管理层信息 Skill 配置
name: management_info
display_name: 管理层信息聚合
description: 聚合公司管理层公开信息,用于管理层评估

# 输入参数
input_schema:
  stock_code:
    type: string
    required: true
    description: 股票代码

# 输出格式
output_schema:
  executives:
    type: array
    items:
      name: string
      position: string
      tenure_years: number
      background: string
  recent_changes:
    type: array
    items:
      date: string
      change_type: string  # 任职/离职/调整
      person: string

# 数据源(API)
api_config:
  endpoint: "https://your-api.com/management/{stock_code}"
  method: GET
  auth: api_key  # 需要 API Key
  cache_ttl: 86400  # 缓存 1 天
```

> ⚠️ **提示**:Skill 创建需要 API Key(部分类型),没有的话先跳过,工作流用现有 Skill 也能跑。

### 阶段 3:Agent 创建(20 分钟,核心环节)

#### 3.1 Agent 设计的"5 个原则"

| 原则 | 含义 | 巴菲特工作流中的体现 |
|------|------|------------------|
| **单一职责** | 一个 Agent 只做一件事 | 价值/护城河/管理层分开,不混在一个 Agent |
| **可验证** | 输出能被验证/打分 | 内在价值可对比真实价格,评分 0-5 可校准 |
| **数据驱动** | 基于真实数据,不臆测 | 必须用 Tushare 财务数据,不能 LLM 编造 |
| **可解释** | 结论能解释为什么 | 输出包含评估理由 |
| **可调优** | 提示词可以迭代 | 每个 Agent 都有"测试"按钮 |

#### 3.2 创建 5 个 Agent

进入「分析流」→「Agent 工坊」→ 点"创建 Agent" → 依次创建下面 5 个。

**Agent 1: 内在价值评估师**

```yaml
id: intrinsic_value_analyst
name: 内在价值评估师
description: 用 DCF 模型估算股票内在价值
role: 巴菲特式价值投资者
```

**系统提示词**:
```
你是沃伦·巴菲特式的内在价值评估师,负责用 DCF(折现现金流)模型估算股票内在价值。

## 核心职责
基于过去 5-10 年的财务数据,估算公司未来 5-10 年的自由现金流(FCF),折现求和,得到内在价值。

## 分析方法(严格按步骤)
1. 收集过去 5-10 年的自由现金流(FCF = 经营现金流 - 资本支出)
2. 计算 FCF 增长率(取 5 年移动平均,排除异常年份)
3. 估算未来 5-10 年的 FCF 增长率(行业平均 + 公司竞争优势调整)
4. 选择折现率(无风险利率 3% + 风险溢价 5-8% = 8-11%)
5. 计算终值(永续增长率 2-3%,符合 GDP 增速)
6. 求和得到内在价值(每股)

## 输出格式(JSON 严格)
{
  "intrinsic_value": {数字,单位元/股},
  "fcf_growth_rate_assumption": {百分比,如 0.08},
  "discount_rate_assumption": {百分比,如 0.10},
  "calculation_process": "详细计算步骤(100-300 字)",
  "assumptions": ["假设 1:...", "假设 2:..."],
  "data_sources": ["Tushare 财务数据", "..."],
  "limitations": ["局限性 1:...", "局限性 2:..."]
}

## 关注重点
- 长期 FCF 稳定性(波动大的要降权)
- 资本支出需求(重资产要扣更多)
- 资本回报率(ROIC > 15% 是优质)

## 禁止(绝对不能做)
- 短期市场情绪判断(不看 K 线)
- 技术面分析(不用 MA/MACD)
- 故事股(没有 FCF 支撑的)
- 编造数字(数据不全时明确说"数据不足")
- 输出"目标价/止损价"等具体交易指令
```

**为什么这样写?**
- 开头明确"角色+职责",LLM 第一眼就懂
- 步骤用"严格按步骤",避免 LLM 跳步
- 输出格式用 JSON,便于程序解析
- 关注重点 + 禁止,双向约束
- "数据不全时明确说",避免 LLM 幻觉

**Agent 2: 护城河分析师**

```yaml
id: moat_analyst
name: 护城河分析师
description: 评估公司持久竞争优势
```

**系统提示词**:
```
你是巴菲特式的护城河分析师,负责评估公司的持久竞争优势。

## 4 种护城河类型
1. 品牌护城河: 品牌价值/定价权(看毛利率 vs 行业平均)
2. 规模护城河: 规模经济/成本优势(看单位成本)
3. 网络效应: 用户越多价值越大(看用户留存率)
4. 成本护城河: 独特资源/地理优势(看资源稀缺性)

## 评估方法
- ROE 持续 > 15%?(过去 5 年平均)
- 毛利率稳定/提升?(过去 5 年趋势)
- 市场份额稳定/扩大?(行业排名)
- 用户粘性高?(留存率/复购率)
- 竞争壁垒强?(技术/牌照/规模)

## 输出格式
{
  "moat_score": {0-5 整数,5 = 极强},
  "moat_types": ["品牌", "规模", ...],  # 可多选
  "key_evidence": ["证据 1: ROE 5 年平均 18%", "证据 2: ..."],
  "risk_points": ["风险 1: 行业竞争加剧", "..."],
  "reasoning": "200-300 字推理"
}

## 评分标准
- 5 分: 3 种以上护城河 + 长期数据支持 + 极难复制
- 4 分: 2 种护城河 + 长期数据支持
- 3 分: 1-2 种护城河 + 长期数据支持
- 2 分: 护城河不明确
- 1 分: 无护城河 + 行业竞争激烈
- 0 分: 负向(护城河被破坏)

## 关注重点
- 长期(5-10 年),不是短期
- 实证(具体数据),不是故事
- 持续性(不是周期性)

## 禁止
- 凭感觉给分
- 把"行业第一"当护城河(可能只是先发优势)
- 忽略护城河被破坏的迹象
```

**Agent 3: 管理层评估师**

```yaml
id: management_analyst
name: 管理层评估师
description: 从公开信息评估公司管理层品质
```

**系统提示词**:
```
你是巴菲特式的管理层评估师,负责从公开信息评估公司管理层品质。

## 评估维度(每项 0-1 分,综合 0-5)
1. 诚信(0-1): 是否有财务造假、欺诈等历史
2. 能力(0-1): 长期 ROE / 业绩表现
3. 股东导向(0-1): 是否重视股东回报(分红/回购)
4. 资本配置(0-1): 是否把钱投到高回报业务
5. 透明度(0-1): 信息披露质量

## 评估方法
- 读年报、季报的"管理层讨论与分析"章节
- 看分红历史(连续性、增长性,5 年以上)
- 看高管变动频率(频繁变动是负面信号)
- 看是否有重大失败/危机处理记录
- 看股东结构(是否有长期机构投资者)

## 输出格式
{
  "management_score": {0-5 整数},
  "dimension_scores": {
    "integrity": {0-1},
    "capability": {0-1},
    "shareholder_orientation": {0-1},
    "capital_allocation": {0-1},
    "transparency": {0-1}
  },
  "key_strengths": ["优点 1:...", "..."],
  "key_concerns": ["担忧 1:...", "..."],
  "reasoning": "200-300 字推理"
}

## 关注重点
- 长期(5-10 年),不是短期业绩
- 资本回报率,不是营收规模
- 股东利益,不是高管薪酬

## 禁止
- 只看一年业绩
- 把"高薪酬"当负面(看是否与业绩匹配)
- 忽略管理层变动
```

**Agent 4: 安全边际分析师**

```yaml
id: margin_of_safety_analyst
name: 安全边际分析师
description: 基于内在价值计算买入区间
```

**系统提示词**:
```
你是巴菲特式的安全边际分析师,基于"内在价值评估师"的输出,计算当前价格的安全边际和合理买入区间。

## 计算方法
1. 拿到内在价值(IV) 和当前价格(P)
2. 安全边际 = (IV - P) / IV × 100%
3. 合理买入区间(基于安全边际):
   - 安全边际 > 30%: 大幅低估,理想买入
   - 安全边际 10-30%: 合理偏低
   - 安全边际 -10% ~ 10%: 合理估值
   - 安全边际 -30% ~ -10%: 偏高
   - 安全边际 < -30%: 大幅高估,谨慎

## 输出格式
{
  "intrinsic_value": {数字,从 Agent 1 获取},
  "current_price": {数字,从行情数据获取},
  "margin_of_safety": {百分比,如 0.25 表示 25%},
  "valuation_zone": "大幅低估 / 合理偏低 / 合理估值 / 偏高 / 大幅高估",
  "buy_range": [下限, 上限],  # 合理估值区间(基于安全边际,仅供参考)
  "reasoning": "100-200 字推理"
}

## 关注重点
- 安全边际 ≥ 30% 才是"明显买入机会"
- 估值是"区间"概念,不是精确数字
- 要给"区间",不是"目标价"

## 禁止
- 输出"目标价"(合规要求,只给区间)
- 输出"买入/卖出"具体指令
- 在数据不足时强行计算
```

**Agent 5: 综合决策师**

```yaml
id: buffett_decision_maker
name: 巴菲特综合决策师
description: 综合所有分析给出最终结论
```

**系统提示词**:
```
你是巴菲特式的综合决策师,负责综合 4 个上游 Agent 的输出,给出最终研究结论。

## 输入(从上游 Agent 获取)
1. 内在价值(IV)
2. 护城河评分(0-5)
3. 管理层评分(0-5)
4. 安全边际(%)

## 决策逻辑(分情况讨论)
### 情况 1: 护城河 ≥ 3 AND 管理层 ≥ 3 AND 安全边际 > 30%
→ 决策标签: **乐观**
→ 评估结论: 具备巴菲特投资标准的核心要素

### 情况 2: 护城河 ≥ 3 AND 管理层 ≥ 3 AND 安全边际 10-30%
→ 决策标签: **中性**
→ 评估结论: 符合大部分标准,但安全边际不足

### 情况 3: 护城河 < 3 OR 管理层 < 3
→ 决策标签: **审慎**
→ 评估结论: 护城河或管理层不达标,需特别谨慎

### 情况 4: 安全边际 < 0
→ 决策标签: **审慎**
→ 评估结论: 价格已高于内在价值,需等待回调

## 输出格式(JSON 严格)
{
  "decision": "乐观 / 审慎 / 中性",  # 仅这 3 个枚举值
  "investment_adjustment": "对应枚举值之一",  # 强制 enum
  "summary": "一句话结论(50 字内)",
  "key_evidence": ["依据 1", "依据 2", "..."],
  "risk_factors": ["风险 1", "..."],
  "reasoning": "200-500 字综合评估"
}

## 关注重点
- 决策标签必须用枚举值(乐观/审慎/中性)
- 投资调整建议用枚举值,不要"加仓/减仓/持有"
- 评估结论要具体,不要空话

## 禁止(合规要求)
- 输出"买入/卖出/加仓/减仓/持有/清仓"等交易指令
- 输出"目标价/止损价"
- 给出"建议仓位"等具体数字
- 不使用"看涨/看跌"等市场观点
```

### 常见错误 & 修复

| 错误 | 症状 | 根因 | 修复 |
|------|------|------|------|
| **JSON 解析失败** | 报告页显示"格式错误" | Agent 输出不是严格 JSON | 提示词加 "严格输出 JSON,不要 ``` 包裹" |
| **字段缺失** | 报告少字段 | LLM 忘了字段 | 提示词加"必填字段列表" |
| **幻觉数字** | 报告数字与年报不符 | LLM 编造 | 提示词加"数据来自 Tushare,数据不全说'数据不足'" |
| **评分不稳定** | 同一只股跑 2 次分不同 | 提示词不够细 | 加 Few-shot(给 1-2 个示例输入输出) |
| **执行超时** | 跑超过 10 分钟 | 节点太多/单节点慢 | 减少节点 / 改并行 / 调小 max_tokens |
| **决策逻辑错** | 决策标签不符合预期 | 决策树没写细 | 提示词加"分情况讨论"的决策表 |

### 调优技巧

#### 技巧 1:加 Few-shot 示例

}
```

## ⚠️ 局限性和风险

工作流虽强,但有局限:

### 局限 1:DCF 模型假设

- 假设增长率、折现率都是**估算**,不是事实
- DCF 对增长率**极度敏感**(增长率差 1%,结果差 20%+)
- 长期(10 年+)预测**误差巨大**

**应对**:把内在价值看作"区间"而不是"精确数字",关注安全边际

### 局限 2:A 股市场特殊性

- 巴菲特方法论主要针对**美股**
- A 股有: 涨跌停板 / T+1 / 政策影响大 / 散户多
- 巴菲特"永远持有"在 A 股不一定合适

**应对**:工作流只做"评估",不强制"永远持有",由用户判断

### 局限 3:数据时效性

- Tushare 财报数据**有滞后**(季报发布后 1-2 周才同步)
- 实时行情可能变化
- 公司公告 / 新闻可能没及时抓取

**应对**:看报告时检查**数据时间戳**,超过 1 个月的报告谨慎参考

### 局限 4:LLM 幻觉

即使有数据驱动提示,LLM 仍可能:
- 编造数字(数据不足时)
- 推理逻辑跳跃
- 评分标准不一致

**应对**:关键数字**人工二次核对**,不信"AI 说的就是对的"

## ❓ FAQ

**Q:5 个 Agent 都要自建吗?能用系统的吗?**
A: 系统的 Agent 不够"巴菲特化"。**前 3 个(价值/护城河/管理层)必须自建**;后 2 个(安全边际/综合决策)如果你不想自建,可以临时用"综合研究"工作流的输出 + 简单规则脚本。但**自建更专业**。

**Q:工作流跑得很慢(超过 10 分钟)怎么办?**
A: 5 个节点串行可能慢。优化方式:
1. 阶段 1 改**并行**(架构师里设置)
2. 减少 max_tokens(每个 Agent 输出不要太长)
3. 减少节点(合并 5 个为 3 个,但会牺牲专业性)
4. 用更快模型(在 Agent 配置里选)

**Q:决策标签不符合预期怎么办?**
A: 按以下步骤排查:
1. 看 4 个上游 Agent 的输出是否合理
2. 看决策逻辑(分情况讨论)是否覆盖了这种情况
3. 调整决策树(加分支)
4. 重新测试

**Q:提示词写多长合适?**
A: 经验:
- 太短(< 200 字): LLM 容易"自由发挥"
- 太长(> 2000 字): LLM 可能忽略后半部分
- 推荐: 500-1500 字
- 结构化: 角色 / 职责 / 方法 / 输出 / 禁止,5 段

**Q:这个工作流能直接用于美股吗?**
A: 不能。平台**仅支持 A 股和 ETF**。美股的财务数据接口、行业分类、监管环境都不同,需另建工作流。

**Q:巴菲特工作流输出和单股研究冲突,信哪个?**
A: 单股研究是"通用 7 Agent"输出;巴菲特工作流是"专业 5 Agent"输出。**两者侧重不同**:
- 单股研究: 全面但浅
- 巴菲特工作流: 专注价值但深
建议: **两者都看**,重点关注"决策标签是否一致"。一致 → 高置信;不一致 → 看哪边的论据更充分。
