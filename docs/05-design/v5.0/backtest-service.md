# 对话驱动回测服务（移交至 v5.0）

## 文档信息

| 项目 | 内容 |
| --- | --- |
| 版本 | v5.0 Candidate |
| 状态 | 延后到 v5.0 规划 |
| 日期 | 2026-05-11 |
| 来源 | 原 `docs/design/v3.0/backtest-service.md` |
| 调整原因 | 功能跨度过大，涉及策略生成、回测引擎、历史数据口径、结果解释、优化闭环与合规边界，当前不纳入 v3.0 / v4.0 验收 |
| 目标 | 在 v5.0 统一纳入“投资系统 / 计划验证 / 复盘增强”主线后再做完整产品化 |

---

## 1. 范围调整说明

对话驱动回测服务原先曾在较早设计文档中作为独立能力出现，但现阶段确认：

- 不再作为 v3.0 功能范围的一部分。
- 不纳入 v4.0 主线验收。
- 整体后移到 v5.0 统一规划。

本次调整的核心原因不是“完全没有原型”，而是该能力的产品边界和工程复杂度明显超出当前版本节奏。若继续放在 v3.0，会造成验收口径过宽、交付质量难以收敛。

---

## 2. 为什么移交到 v5.0

回测能力至少同时包含以下子问题：

1. 自然语言策略理解与参数确认。
2. 策略 DSL / Python 生成与安全校验。
3. 历史数据质量、基准、复权、股票池口径统一。
4. 独立回测引擎隔离与资源控制。
5. 回测结果可视化、解释与风险提示。
6. 评估、优化、再回测闭环。
7. 与投资计划验证、交易复盘增强的产品衔接。

这些问题彼此强耦合，拆成 v3.0 的一个“可验收单点功能”并不合适，更适合作为 v5.0 的系统级能力统一推进。

---

## 3. 可复用的现有资产

虽然本能力后移，但现有仓库中的部分实现和原型仍可作为 v5.0 的起点：

| 资产 | 位置 | 可复用说明 |
| --- | --- | --- |
| API 路由原型 | `app/routers/backtest.py` | 可作为后续 API 契约草稿 |
| 业务服务原型 | `app/services/backtest_service.py` | 可复用会话管理与调用编排思路 |
| 策略分析器 | `core/backtest/strategy_analyzer.py` | 可复用策略可行性分析框架 |
| 策略生成器 | `core/backtest/strategy_generator.py` | 可复用生成链路，但需重新审视安全与口径 |
| 结果评估器 | `core/backtest/result_evaluator.py` | 可复用评估维度设计 |
| 迭代优化器 | `core/backtest/iterative_optimizer.py` | 可复用“执行→评估→优化”闭环原型 |
| 引擎客户端 | `core/backtest/engine_client.py` | 可复用独立服务调用模式 |
| 前端页面原型 | `frontend/src/views/Backtest/index.vue` | 可复用页面结构，但不作为当前版本交付承诺 |

这些资产现在的定位是“候选原型”，不是 v3.0 / v4.0 已承诺上线能力。

---

## 4. v5.0 再立项前必须先补齐的前置问题

在 v5.0 正式立项前，建议先明确以下问题，否则回测功能仍然容易变成大而散的系统：

### 4.1 产品定位

需要先回答：

- 回测是独立工具，还是投资计划验证的附属能力？
- 用户的核心入口是“自然语言策略实验”，还是“计划验证 / 复盘验证”？
- 回测结果最终服务于研究、计划、还是交易纪律管理？

### 4.2 数据与口径

需要统一：

- 历史行情与基准来源
- 复权方式
- 股票池与成分股时点口径
- 指标统计口径
- ETF / 指数 / 个股的适配边界

### 4.3 安全与执行隔离

需要明确：

- 策略代码执行边界
- 资源限制与超时
- 用户隔离
- 第三方库白名单
- 风险提示与免责声明输出标准

### 4.4 验收标准

v5.0 再做时，必须先定义清楚：

- 最小支持的策略类型
- 最小支持的资产范围
- 最小可接受的结果解释能力
- 哪些场景能自动优化，哪些只能给建议

---

## 5. 暂定的 v5.0 目标链路

建议后续按以下主链路收敛，而不是同时铺太多入口：

1. 用户提出策略或计划验证问题。
2. 系统分析可行性并要求补齐关键参数。
3. 用户确认后生成结构化策略定义。
4. 调用独立回测服务执行。
5. 返回结构化结果、关键指标和风险提示。
6. 允许基于评估结果做一次受控优化。
7. 将结果挂回投资计划验证或复盘增强链路。

---

## 6. 当前结论

回测服务保留，但从 v3.0 版本范围移除，并明确不作为 v4.0 主线交付。

后续统一在 v5.0 中推进，避免在当前版本中以“大功能半完成态”进入验收。
