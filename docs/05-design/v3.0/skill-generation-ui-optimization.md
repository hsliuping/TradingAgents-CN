# Skill 生成系统 — 交互界面优化建议

> 基于 `skill-generation-system.md` 设计文档与当前 `SkillGeneration.vue` 实现的分析，提出交互优化建议。

**分析日期**: 2026-02-22  
**当前实现**: `frontend/src/views/Workflow/SkillGeneration.vue`

---

## 一、与设计文档的差异概览

| 设计文档要求 | 当前实现 | 建议 |
|-------------|---------|------|
| 四步流程：需求沟通 → **规格确认** → 代码生成 → 完成 | 规格确认步骤被合并/跳过 | 恢复独立规格确认页 |
| WebSocket 推送真实生成进度 | 使用 `setInterval` 模拟进度 | 接入 WebSocket 或轮询 |
| 规格书表格展示（参数、输出格式等） | 无规格书展示 | 新增规格确认卡片 |
| 测试支持自定义参数 | 测试使用默认参数 | 支持用户输入测试参数 |
| 代码查看带语法高亮 | 纯 textarea 只读 | 使用 Monaco / highlight.js |

---

## 二、核心优化建议

### 2.1 恢复「规格确认」独立步骤（高优先级）

**问题**：设计文档中规格确认是独立步骤，用户应在生成前看到完整 SkillSpec 并确认。当前实现中 `canConfirm` 仅依赖 `chatMessages.length >= 2`，用户可能在不清楚最终规格的情况下就点击「确认并生成」。

**建议**：

1. **在最后一轮对话后展示规格预览**  
   - 当 `is_final_round` 或 `current_round >= expected_rounds` 时，从 API 获取 `spec_preview`（若后端支持）或从最后一轮 AI 回复中解析出规格信息。
2. **新增规格确认卡片**（参考设计文档 12.2）：
   ```
   ┌─────────────────────────────────────────────────────────┐
   │  📄 工具规格确认                                         │
   │  基本信息：工具 ID、名称、分类、数据源                     │
   │  输入参数：表格展示 参数 | 类型 | 必填 | 说明              │
   │  边界检查：复杂度 X/5，在 Skill 范围内                    │
   │  [✅ 确认并生成]     [✏️ 返回修改]                        │
   └─────────────────────────────────────────────────────────┘
   ```
3. **后端扩展**：`respond` 接口在最后一轮时返回 `spec_preview`（当前 SkillSpec 草稿），前端据此渲染规格确认页。

---

### 2.2 生成进度与后端同步（高优先级）

**问题**：当前 `genProgress` 和 `genSteps` 由前端定时器模拟，与真实管线阶段不同步，用户无法感知实际进度（如重试、失败阶段）。

**建议**：

1. **方案 A：WebSocket 推送**（设计文档 11.3）  
   - 后端在 `confirm_spec` 执行管线时，通过 WebSocket 推送 `stage`、`message`、`progress`、`iteration` 等。
   - 前端建立 `WS /api/skill-generation/sessions/{session_id}/progress` 连接，实时更新 UI。

2. **方案 B：轮询**（实现成本更低）  
   - 后端在 `skill_creation_sessions` 中记录 `pipeline_stage`、`pipeline_message`、`iteration`。
   - 前端在生成阶段每 1–2 秒轮询 `GET /sessions/{session_id}`，根据 `pipeline_stage` 更新进度条和步骤状态。

3. **展示迭代信息**：当发生重试时，显示「第 X 轮未通过 (Y 分)，正在重试...」，提升透明度和信任感。

---

### 2.3 对话体验优化（中优先级）

**问题**：AI 回复可能包含表格、列表等结构化内容，当前仅做 Markdown 渲染，可读性和引导性有提升空间。

**建议**：

1. **Markdown 表格样式**：确保 `marked` 正确渲染表格，并增加 `.msg-text table` 的样式（边框、斑马纹等）。
2. **结构化消息组件**：若 AI 返回 JSON 格式的结构化内容（如「功能点 | 理解 | 需要确认」），可解析后渲染为 `el-descriptions` 或 `el-table`，提升可读性。
3. **快捷回复**：在 AI 提问时，提供若干快捷回复按钮（如「A股就行」「选方案 A」「确认」），减少输入成本。
4. **输入方式**：增加「Enter 发送、Shift+Enter 换行」的选项，并在设置中可配置。

---

### 2.4 测试功能增强（中优先级）

**问题**：测试使用默认参数，无法验证不同输入下的行为。

**建议**：

1. **参数表单**：在测试对话框中，根据 Skill 的 `parameters` 动态生成表单，用户可填写 `stock_code`、`limit` 等。
2. **默认值**：从 `spec.test_input` 或 `parameters[].default` 预填表单。
3. **多组测试**：支持保存多组测试用例，一键切换执行。

---

### 2.5 代码查看体验（中优先级）

**问题**：代码在只读 textarea 中展示，无语法高亮和行号，长代码阅读困难。

**建议**：

1. **语法高亮**：使用 `highlight.js` 或 `shiki` 对 Python 代码高亮。
2. **行号**：增加行号列，便于定位。
3. **复制按钮**：一键复制完整代码。
4. **可选**：集成 Monaco Editor（只读模式），支持搜索、折叠等。

---

### 2.6 Skill 列表与筛选（中优先级）

**问题**：仅支持按状态筛选，缺少分类、搜索等能力。

**建议**：

1. **分类筛选**：后端已支持 `category` 参数，前端增加分类下拉（news、market、fundamentals 等）。
2. **搜索**：支持按 `display_name`、`tool_id`、`description` 关键词搜索（需后端支持或前端过滤）。
3. **操作列优化**：操作按钮过多（7 个），可改为下拉菜单或「更多」折叠，保留常用操作（测试、代码、启用/禁用）直接展示。

---

### 2.7 草稿恢复与步骤一致性（中优先级）

**问题**：`resumeSession` 在 `status === 'confirmed'` 时设置 `wizardStep = 1`，但步骤 1（规格确认）的 UI 被注释/合并，导致恢复后显示空白。

**建议**：

1. **统一步骤定义**：明确四步为 0=需求沟通、1=规格确认、2=生成中、3=完成。
2. **恢复步骤 1 UI**：实现规格确认页，从 `session.spec` 渲染。
3. **草稿恢复逻辑**：
   - `gathering` → 步骤 0，可继续对话；
   - `confirmed` → 步骤 1，展示规格，可点击「确认并生成」进入步骤 2；
   - `generating` → 步骤 2，显示进度（若支持轮询可拉取最新状态）。

---

### 2.8 完成页与后续操作（低优先级）

**问题**：生成成功后仅提供「查看 Skill 列表」和「关闭」，缺少快捷操作。

**建议**：

1. **快捷操作**：增加「查看代码」「立即测试」「复制 tool_id」按钮。
2. **绑定引导**：提示「可在 配置Tools / 配置Agent 中将此 Skill 绑定到 Agent」。
3. **评分详情**：若后端返回各维度评分（executability、authenticity 等），可展示雷达图或简要说明。

---

### 2.9 边界警告与引导（低优先级）

**问题**：边界警告使用 `boundaryCheck?.concerns`、`decomposition_suggestions`，需与后端 `BoundaryCheck` 字段保持一致。

**建议**：

1. **字段兼容**：确认 API 返回的字段名（如 `violations` vs `concerns`），统一前后端。
2. **引导文案**：当 `within_boundary === false` 时，用更友好的文案说明「建议拆分为多个 Skill」，并列出 `suggested_skills`。
3. **复杂度可视化**：用进度条或星级展示 `complexity_score`（1–5）。

---

### 2.10 响应式与无障碍（低优先级）

**建议**：

1. **对话区高度**：`55vh` 在小屏可能偏小，可改为 `min-height` + `flex: 1` 或使用 `calc(100vh - 某固定值)`。
2. **键盘导航**：确保对话框内 Tab 顺序合理，支持 Esc 关闭。
3. **加载状态**：为长时间操作（生成、优化）提供明确的「预计耗时」提示，减少焦虑。

## 三、实施优先级建议

| 优先级 | 项目 | 预估工作量 | 收益 |
|-------|------|-----------|------|
| P0 | 恢复规格确认步骤 | 1–2 天 | 符合设计、降低误操作 |
| P0 | 生成进度与后端同步 | 1–2 天 | 真实反馈、提升信任 |
| P1 | 测试支持自定义参数 | 0.5 天 | 验证能力增强 |
| P1 | 草稿恢复步骤一致性 | 0.5 天 | 草稿可用性 |
| P1 | 代码语法高亮 + 复制 | 0.5 天 | 阅读体验 |
| P2 | 分类筛选 + 操作列优化 | 0.5 天 | 列表易用性 |
| P2 | 快捷回复 / 输入方式 | 0.5 天 | 对话效率 |
| P3 | 完成页快捷操作 | 0.5 天 | 流程连贯 |
| P3 | 边界警告优化 | 0.5 天 | 引导清晰 |

---

## 四、后端需配合的改动（简要）

1. **`respond` 接口**：最后一轮时返回 `spec_preview`（SkillSpec 草稿）。
2. **`confirm_spec` 或会话**：支持记录 `pipeline_stage`、`pipeline_message`、`iteration`，供轮询或 WebSocket 使用。
3. **WebSocket（可选）**：`/api/skill-generation/sessions/{session_id}/progress` 推送进度事件。

---

## 五、总结

当前实现已覆盖核心流程（需求沟通、生成、列表管理、测试、优化），但与设计文档相比，**规格确认步骤缺失**和**生成进度模拟**是影响体验的主要缺口。优先补齐这两项，再逐步优化测试、代码查看、列表筛选等，可显著提升 Skill 工坊的可用性和专业感。
