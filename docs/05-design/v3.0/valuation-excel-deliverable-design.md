# 估值测算 Excel 交付物设计（声明式交付物 · A10-D1）

> 状态：规划完成，开发中
> 关联：demo 合作展示（火山引擎 Seed-Evolving）、智能助手层产品增强
> 版本基线：v3.x（分支 v3.6-community）

## 1. 背景与诉求

### 1.1 合作方反馈

demo 合作方（火山引擎）建议：

1. demo 增加更多**实体交付物**，不要只有文本报告
2. 展示 **Seed-Evolving 生成 Excel 金融建模**的能力
3. 能力现状（对方原话口径）：比之前提升很多，错误率高于 GPT 5.6，但优于 GLM 5.3 / Qwen 3.8 Max——**可以上，需兜底**

### 1.2 现状盘点

- **报告能力**：固定分析流程产出全链路报告包，实测深度档 5.1 万字符 / 20 小节，快速档也有 3.9 万字符起步——demo 台词"3000 字报告"严重低估产品，需修正为"完整研究报告"
- **Excel 能力**：**不存在**。全库仅 portfolio 导入（read_excel）和备份有 xlsx 触点，无任何生成代码；openpyxl 3.1.5 随 pandas 在环境中但未声明依赖
- **可复用资产**：
  - Skill 生成管线（自然语言 → 规格 → 代码 → 静态校验 → 沙箱执行 → 质量评估 → 迭代修复）完整可用
  - 智能助手已有 Plan-then-Execute（种子流程匹配 → LLM 规划 → ReAct 回退）与会话报告附件机制
  - v4.0 设计中的金融 Schema 体系（`docs/05-design/v4.0/financial-schema-examples/`）已定义 PE/PB/PEG 的 output_contract / verifier_rule / applicability_rule——测算表的估值层直接对齐

## 2. 产品定位决策（两层架构分工）

产品有两层，Excel 交付物**只在智能助手层承接**：

| 层 | 产品契约 | 在本需求中的角色 |
|---|---|---|
| 固定分析流程 | 固定的过程 → 固定的产出（报告包） | **能力提供者**：产出报告包，Excel 的数据从它来；流程零改动 |
| 智能助手 | 听懂要什么 → 调度能力 → 组合交付 | **需求承接者 + 交付物组织者**：识别交付物清单，按需调度，对话内交付 |

**明确不做**：给固定流程加 Excel 环节。理由：要么所有分析平添负担，要么加开关破坏"固定"契约。

### 2.1 声明式交付物原则

- 报告包是**默认交付物**，用户不声明就只有它，体验零变化
- 测算表是**声明式可选交付物**：用户在请求中明确要求（初始声明或对话追加）才生成
- 交付物清单进入助手意图模型：默认 `[研究报告包]`，声明后追加 `[估值测算表]`（后续可扩展图表等类型）

### 2.2 产品叙事

报告回答"判断是什么、证据是什么"（结论层）；测算表回答"测算过程是什么、改一个假设结论怎么变"（工作底稿层）。测算表把"低幻觉、证据溯源"主张从文字层延伸到数字层：每个数字要么来自真实数据、要么来自明确标注的假设，公式可审计。

## 3. 能力架构：三层分离

```
智能助手（意图识别：交付物清单）
   │ 识别到 [估值测算表]
   ▼
① 规格生成层（Seed-Evolving，秀场）
   输入：报告包（investment_plan / fundamentals_report / 财务数据）
   输出：模型规格 JSON（盈利预测假设 / 估值倍数 / 情景区间 / 数据引用）
   ▼
② 确定性渲染层（openpyxl，保险）
   规格 JSON → .xlsx（真实公式、假设单元格、情景区间）
   不依赖模型，规格合法则必然产出可打开、公式有效的文件
   ▼
③ 沙箱校验层（叙事）
   重开文件 → 公式存在性 → 输入值与规格一致 → 计算自洽
   不通过 → 打回 ① 重新生成（失败重试本身就是演示亮点）
```

设计意图：**模型错误率高的弱点被 ②③ 接住**。规格错了校验层拦截并触发重生成；文件层永不翻车。

## 4. 测算表设计

### 4.1 工作簿结构（两个 Sheet）

**Sheet1 盈利推演**

| 期间 | 营收（亿元） | 营收增速 | 净利率 | 归母净利润（亿元） |
|---|---|---|---|---|
| 2024A | 1450.0 | - | - | 59.5 |
| 2025A | 1451.8 | 0.1% | 4.1% | 59.5 |
| 2026E | =上期×(1+增速) ← 公式 | 25%（假设格） | 6.0%（假设格） | =营收×净利率 ← 公式 |
| 2027E | 同上 | 20% | 6.5% | 同上 |

- 历史行（A）为真实数据落格；预测行（E）增速/净利率为**假设输入格**，营收与净利润为**公式格**
- 用户改假设格，公式结果随之变化——"可调参的白盒模型"

**Sheet2 估值情景**

| 情景 | 方法 | 倍数（假设格） | EPS 基准 | 目标价（公式格） |
|---|---|---|---|---|
| 悲观 | PE | 15 | 2026E | =EPS×倍数 |
| 中性 | PE | 22 | 2026E | … |
| 乐观 | PE | 30 | 2027E | … |

- EPS = 净利润 ÷ 总股本（跨 Sheet 引用盈利推演）
- 每行附方法适用性检查与比较基准说明（对齐 v4.0 output_contract 的 must_state_* 要求）

### 4.2 规格 JSON 契约（①→② 的接口）

```json
{
  "ticker": "601127",
  "stock_name": "赛力斯",
  "analysis_date": "2026-09-10",
  "share_count": 15.1,
  "current_price": 130.0,
  "earnings_forecast": {
    "history": [
      {"period": "2024A", "revenue": 1450.0, "net_profit": 59.5}
    ],
    "assumptions": [
      {"period": "2026E", "revenue_growth": 0.25, "net_margin": 0.06,
       "rationale": "新车型放量……"}
    ]
  },
  "valuation": {
    "scenarios": [
      {"name": "中性", "method": "PE", "multiple": 22, "eps_period": "2026E",
       "benchmark_basis": "同业 22-28 倍区间",
       "applicability_check": {"passed": true, "notes": ["归母净利润为正"]}}
    ],
    "risk_notes": ["……"]
  }
}
```

### 4.3 校验规则（③，对齐 v4.0 verifier_rule）

| 规则 | 级别 | 说明 |
|---|---|---|
| 必填字段完整 | 阻断 | 对齐 `contract.valuation.*` 的 required_fields |
| 方法适用性 | 阻断 | PE 要求正盈利（`rule.pe_requires_positive_earnings`）；银行优先 PB；PEG 要求有意义增长 |
| 假设非平凡 | 阻断 | 增速/净利率/倍数缺失或为零 |
| 公式存在性 | 阻断 | 预测行与目标价必须是公式格，不能是死值 |
| 输入一致性 | 阻断 | 文件中的假设值与规格 JSON 完全一致 |
| 计算自洽 | 阻断 | Python 重算期望值与公式引用关系一致 |
| 目标价合理区间 | 警告 | 目标价偏离现价 ±80% 外提示复核（不阻断） |

## 5. Demo 场景映射

| Demo 环节 | 本需求的动作 |
|---|---|
| 输入句 | 修正为"交付完整研究报告 + 一张未来 2 年盈利、估值测算表格" |
| 环节 1-4 | 助手调度固定分析流程（原样），报告包自己说话 |
| 环节 5 | Skill 中心：Seed-Evolving 生成测算表技能（规格生成）→ 沙箱验证 → 迭代修复 |
| 收尾 | 对话内交付：报告卡片 + Excel 下载卡片 |

彩排与兜底：赛力斯真实数据预跑 5-10 次统计一次通过率；现场失败 → 重试（叙事内）→ 预生成文件（叙事外）→ 演示视频（最后防线）。

## 6. MVP 范围与非目标

**做**：
1. `core/deliverables/valuation_excel.py`：渲染器（规格 → xlsx）+ 校验器（重开验证）
2. `core/deliverables/valuation_spec_generator.py`：规格生成层（LLM 从报告包提取判断 + 注入真实数据锚点 + 校验失败反馈重试）
3. Skill 化封装（module+function 注册，助手可调用）
4. openpyxl 声明为直接依赖

**不做（本期）**：
- 固定流程加 Excel 环节（明确否决）
- 交付物类型的产品化 UI（报告之外的附件管理界面）
- PB / PEG / DCF（当前目标价公式为 EPS×倍数，仅适配 PE；PB 需每股净资产、PEG 需增长率公式，随 v4.0 金融 Schema 落地后开放）
- 图表类交付物

### 7.1 已知数据缺口（demo 数据准备）

- `stock_financial_data` 无年报数据（仅季度）——财务历史当前用季度 TTM 口径（`revenue_ttm`/`net_profit_ttm`）
- 总股本无独立数据源（真实验证中硬编码 15.1 亿股），需接入股本/市值数据
- `market_quotes.current_price` 存在滞后（同步频率待确认）

## 8. 真实验证记录（2026-09-12）

Seed-Evolving（doubao-seed-evolving，volcengine）+ 赛力斯 601127 真实报告包：

- 规格生成：**第 1 次尝试通过**（约 73 秒），无需重试
- 预测假设：2026E 增速 -12% / 净利率 2.9%（引用 Q1 营收环比 -52.8%、经营现金流 -209.5 亿）；2027E +8% / 3.2%——方向与研究结论（中性偏审慎）一致
- 估值情景：PE 10 / 14 / 20，基准引用材料内可比（上汽 11.49 / 长城 14.61 / 行业中位 16.05 / 历史中位 32.90 倍）
- 产物：`data/deliverables/real_seed_evolving_601127.xlsx`（校验全绿，无警告）
