# TradingAgents-CN v3.1.0 验收测试计划

## 文档目的

本计划用于 `v3.1.0` 小版本验收。

该版本聚焦“跟踪闭环”，目标是让用户从一次性使用转向持续复访。

## 版本定位

- 版本主题：跟踪闭环版
- 目标用户：高频使用者、老用户
- 发布形态：GA
- 核心目标：让用户形成“跟踪 -> 提醒 -> 复盘 -> 计划”的闭环

## 纳入范围

1. 定时分析。
2. 统一通知中心。
3. QQ Gateway 与 IM 推送。
4. 持仓分析。
5. 交易复盘。
6. 投资计划。

## 不纳入范围

1. MCP Server。
2. QMT 和 ETF。
3. AI 工作流架构师、Agent 工坊、Skill 自动生成。
4. 回测服务。

## 验收重点

1. 跟踪对象是否能按计划持续触发分析。
2. 分析完成后是否能通过站内与 QQ 渠道稳定触达。
3. 持仓、复盘、投资计划是否能形成真实的复访理由。

## 核心验收场景

### 场景 A：定时分析调度

1. 创建一条定时分析。
2. 暂停该配置。
3. 重新启用该配置。

预期结果：

1. 配置能成功创建。
2. 状态切换正确。
3. 后续任务触发节奏符合配置预期。

### 场景 B：统一通知触达

1. 触发一项分析任务。
2. 检查站内通知。
3. 检查 QQ 侧消息推送。

预期结果：

1. 通知中心能看到对应事件。
2. QQ 渠道能收到与任务一致的推送。
3. 站内与外部通知内容不冲突。

### 场景 C：QQ 会话接入

1. 通过 QQ 渠道发起多轮对话。
2. 切换不同 session 来源。
3. 验证身份绑定后查询个人相关数据。

预期结果：

1. Session 隔离正确。
2. 用户映射正确。
3. 不会跨用户读取持仓、计划或复盘信息。

### 场景 D：持仓分析

1. 列出持仓。
2. 查看指定持仓的分析详情。

预期结果：

1. 列表可读、可筛选。
2. 详情内容足够支撑继续观察或决策准备。

### 场景 E：交易复盘与投资计划

1. 查看复盘列表与详情。
2. 查询当前投资计划。

预期结果：

1. 复盘与计划可作为后续跟踪依据，而不是孤立页面。
2. 用户能理解这些页面与助手、通知之间的关系。

## 入口条件

1. 调度器、通知、QQ Gateway 在测试环境可用。
2. 持仓、复盘、投资计划有可验证的测试数据。
3. 已准备至少一个完整的 QQ 绑定测试账号。

## 退出条件

1. 定时分析、站内通知、QQ 推送全链路通过。
2. 持仓、复盘、投资计划页面不存在阻塞级空数据或错用户问题。
3. 关键留存闭环可被测试人员连续走通，不依赖手工修数据。

## 风险提示

1. 调度、通知、IM 是跨模块链路，局部看似可用不代表整体可发布。
2. 如果 QQ 身份映射和通知一致性不稳，会直接影响用户信任感。
