# v2.0 股票数据对接表

## 概述

本文档面向以下角色：

- 外部数据供应商
- 内部数据同步服务开发者
- 接口适配层开发者
- 数据库建模与 ETL 开发者

本文档回答的问题不是“分析要什么”，而是“对接时到底应该传什么字段、字段如何命名、哪些字段必须传、哪些字段可以缺省、如何映射到 v2.0 内部字段”。

建议与以下文档配合阅读：

- [docs/design/v2.0/v2.0-stock-data-requirements.md](docs/design/v2.0/v2.0-stock-data-requirements.md)

## 对接原则

### 1. 主键原则

建议所有股票类数据统一使用以下标识：

- 内部主键：code
- 可选兼容键：symbol

推荐规则：

| 场景 | 推荐值 |
|---|---|
| A 股内部主代码 | 600519 |
| A 股带交易所代码 | 600519.SH |
| 港股 | 0700.HK |
| 美股 | AAPL |

### 2. 日期原则

统一建议：

- 日期字段：YYYY-MM-DD
- 日期时间字段：ISO 8601 或可转为 datetime 的标准格式
- 交易日字段命名优先使用 trade_date
- 发布时间字段命名优先使用 publish_time
- 更新时间字段命名优先使用 updated_at

### 3. 数值原则

- 价格字段统一使用 number
- 百分比字段优先使用数值型，不带百分号
- 金额字段保持原始货币单位，不混入字符串单位
- 对于无法提供的数据，返回 null，不要返回空字符串伪装数值字段

### 4. 来源原则

所有可落库数据建议带 source 或 data_source 字段，用于多源优先级控制和问题排查。

## 一、股票主数据对接表

目标集合：stock_basic_info

### 1.1 必传字段

| 内部字段 | 类型 | 必传 | 供应方常见字段名 | 示例 | 说明 |
|---|---|---|---|---|---|
| code | string | 是 | code, stock_code, symbol, sec_code | 600519 | 内部主代码，A 股建议存 6 位代码 |
| symbol | string | 否 | ts_code, wind_code, full_code | 600519.SH | 带市场后缀代码 |
| name | string | 是 | name, stock_name, sec_name, security_name | 贵州茅台 | 股票名称 |
| industry | string | 是 | industry, sw_industry, jq_industry, level1_industry | 白酒 | 一级行业即可 |
| market | string | 是 | market, board, market_name, list_board | 主板 | 主板 / 创业板 / 科创板等 |
| source | string | 是 | source, data_source, vendor | tushare | 数据来源 |

### 1.2 建议字段

| 内部字段 | 类型 | 必传 | 供应方常见字段名 | 示例 | 说明 |
|---|---|---|---|---|---|
| area | string | 否 | area, region, province | 贵州 | 地域信息 |
| list_date | string/date | 否 | list_date, ipo_date, listed_date | 2001-08-27 | 上市日期 |
| exchange | string | 否 | exchange, exchange_code | SSE | 交易所 |
| current_price | number | 否 | last_price, latest_price, current_price | 1688.00 | 可作为备用字段 |
| total_mv | number | 否 | total_mv, market_cap, total_market_value | 2100000000000 | 总市值 |
| circ_mv | number | 否 | circ_mv, float_mv, free_float_mv | 2050000000000 | 流通市值 |
| pe | number | 否 | pe, pe_static | 25.30 | 静态 PE |
| pb | number | 否 | pb, pb_ratio | 9.52 | PB |
| pe_ttm | number | 否 | pe_ttm | 24.80 | TTM PE |
| pb_mrq | number | 否 | pb_mrq | 9.48 | MRQ PB |
| turnover_rate | number | 否 | turnover_rate, turnoverratio | 0.42 | 换手率 |
| volume_ratio | number | 否 | volume_ratio, vol_ratio | 1.18 | 量比 |
| updated_at | datetime | 否 | updated_at, sync_time, update_time | 2026-03-20T15:05:00 | 更新时间 |

### 1.3 标准化规则

- A 股 code 建议统一去掉后缀，symbol 保留后缀
- industry 建议优先映射为稳定一级行业，避免粒度过细导致行业维度碎片化
- market 建议使用内部统一值，如 主板、创业板、科创板、北交所

## 十一、验收清单

数据供应方完成对接后，建议按以下清单验收：

### 11.1 字段层验收

- 必传字段是否全部可用
- 数值字段是否为 number 而非字符串
- 日期字段格式是否统一
- code / symbol 是否统一规则
- source / data_source 是否可追踪

### 11.2 数据质量验收

- 是否存在大量 null 核心字段
- 是否存在 trade_date 断档
- 是否存在重复主键
- 是否存在 code 与 symbol 对不上的情况
- 新闻与社媒时间是否可排序

### 11.3 业务验收

- 能否支撑单股分析完整执行
- 能否生成市场分析报告
- 能否生成基本面分析报告
- 能否生成新闻分析报告
- 行业与大盘分析是否有足够数据支持

## 十二、推荐对接优先顺序

如果供应方能力有限，推荐按以下顺序逐步交付：

1. 股票主数据
2. 最新行情快照
3. 历史日线行情
4. 基本面财务
5. 新闻公告
6. 指数环境
7. 行业板块
8. 社媒情绪
9. 筹码分布

这个顺序可以保证 v2.0 先具备基础分析能力，再逐步补齐高阶判断能力。
