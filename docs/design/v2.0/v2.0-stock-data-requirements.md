# v2.0 股票数据需求清单

## 概述

本文档用于明确 TradingAgentsCN v2.0 股票分析引擎所需的数据范围、字段级要求、数据优先级以及库表映射关系。

目标不是描述“理论上分析股票可能需要什么数据”，而是回答以下三个工程问题：

1. v2.0 当前主工作流实际依赖哪些股票数据
2. 这些数据需要细化到哪些字段
3. 如果要做数据同步、数据建模、上线裁剪，哪些字段是必须的，哪些字段是增强项

本文档适用范围：

- v2.0 单股分析主工作流
- v2.0 批量分析复用链路
- v2.0 研究经理、交易员、风险经理依赖的上游股票分析数据

配套文档：

- [docs/design/v2.0/v2.0-stock-data-provider-mapping.md](docs/design/v2.0/v2.0-stock-data-provider-mapping.md)

不包含：

- 持仓分析专属账户字段
- 交易复盘专属订单字段
- ETF 专属基金字段

---

## 工作流视角的数据范围

v2.0 股票分析主工作流包含以下关键节点：

1. 大盘分析师
2. 板块分析师
3. 市场分析师
4. 基本面分析师
5. 新闻分析师
6. 社交媒体分析师
7. 看多研究员 / 看空研究员
8. 研究经理
9. 交易员
10. 风险分析师组
11. 风险经理

其中，前 6 个分析师节点直接消耗股票数据，研究经理还会委托筹码分布分析师补充判断。因此，v2.0 的股票数据需求可以拆分为 8 个数据域：

1. 股票主数据
2. 个股行情与技术面数据
3. 大盘 / 指数环境数据
4. 行业 / 板块数据
5. 基本面 / 财务数据
6. 新闻 / 公告数据
7. 社媒 / 情绪数据
8. 筹码分布数据

## 一、股票主数据

股票主数据用于工作流初始化、提示词变量注入、行业映射、市场识别、货币识别，以及后续所有分析节点的上下文构建。

### 1.1 必需字段

| 字段名 | 类型 | 必需 | 示例 | 说明 |
|---|---|---|---|---|
| code | string | 是 | 600519 | 6 位股票代码或统一主代码 |
| symbol | string | 否 | 600519.SH | 带交易所后缀代码，便于跨源兼容 |
| name | string | 是 | 贵州茅台 | 股票名称 |
| industry | string | 是 | 白酒 | 所属行业，用于板块分析和行业维度注入 |
| market | string | 是 | 主板 | 上市板块或市场层级 |
| source | string | 是 | tushare | 主数据来源 |
| area | string | 否 | 贵州 | 地域信息，可用于扩展分析 |
| list_date | string/date | 否 | 2001-08-27 | 上市日期 |
| current_price | number | 否 | 1688.00 | 备用当前价，主来源仍建议走行情表 |

### 1.2 建议补充字段

| 字段名 | 类型 | 必需 | 示例 | 说明 |
|---|---|---|---|---|
| is_st | bool | 否 | false | 是否 ST，可提前标记风险 |
| exchange | string | 否 | SSE | 交易所代码 |
| market_type | string | 否 | A股 | 市场大类 |
| currency_name | string | 否 | 人民币 | 计价货币名称 |
| currency_symbol | string | 否 | ¥ | 计价货币符号 |

### 1.3 主要用途

- 构造 company_name、industry、market_name、currency_name、currency_symbol 等系统变量
- 提供行业映射给板块分析师和研究经理
- 作为新闻、情绪、财务、行情等多类数据的统一关联键

## 三、大盘 / 指数环境数据

大盘分析师负责回答市场整体风险偏好、趋势状态和系统性风险，不依赖单只股票本身，而依赖指数和盘面数据。

- 上证指数

- 中证 500

### 3.5 QMT 模式差异

如果走 QMT 模式，则可接受字段范围收缩为：

- 指数趋势
- 市场扩散度
- 成交活跃度
- 风格切换
- 盘面结构

但以下字段不应作为硬依赖：

- 北向资金官方口径
- 两融官方口径
- 涨跌停官方统计
- 指数估值快照

### 3.6 推荐统一表结构

为了便于数据提供商一次性按统一格式交付，大盘 / 指数环境数据建议按以下几张标准表组织，而不是按内部工具拆分理解。

| 表名 | 用途 | 主键建议 | 说明 |
|---|---|---|---|
| index_daily_quotes | 指数日线行情 | index_code + trade_date | 存放主要指数的日线序列，用于趋势、均线、技术指标、市场周期分析 |
| index_valuation_daily | 指数估值与规模快照 | index_code + trade_date | 存放指数 PE、PB、换手率、市值等估值快照 |
| market_breadth_daily | 市场宽度与两市成交统计 | trade_date + market_scope | 存放沪深两市或全市场涨跌家数、成交额、成交量、上市公司数量等统计 |
| market_connect_flow_daily | 互联互通资金流向 | trade_date | 存放北向 / 南向资金净流入数据 |
| market_margin_daily | 两融汇总数据 | trade_date + exchange_id | 存放沪市、深市融资融券汇总口径 |
| market_limit_stats_daily | 涨跌停与盘面分布统计 | trade_date | 存放涨跌停、炸板、涨跌分布等盘面结构统计 |

|---|---|---|---|---|
| code | string | 是 | 600519 | 股票代码 |

### 4.7 交付边界说明

为了避免对接时对“交明细还是交聚合”产生歧义，行业 / 板块数据建议按以下边界理解：

- stock_industry_mapping、stock_sector_mapping、sector_daily_quotes、sector_fund_flow_daily、industry_peer_snapshot 属于主链路推荐标准表。
- sector_constituents_snapshot 属于增强表，但如果对方已有板块成分股能力，建议一次性纳入交付。
- industry_pe_median、industry_pb_median、industry_pe_mean、industry_pb_mean、target_rank_by_mv 这类聚合或排序字段，建议由平台基于 industry_peer_snapshot 派生，不作为必须由供应商落表的硬要求。

## 五、基本面 / 财务数据

基本面分析师负责分析公司财务健康状况、盈利能力、成长性和估值水平，是 v2.0 的核心数据域之一。

补充评估结论：

- 如果目标只是让 v2.0 主流程先跑通，5.7 的最小可用要求基本够用。
- 如果目标是一次性交付到位，避免后续为详情页、筛选器、研究增强反复补数，则应把财务子表原始结构一并纳入交付范围。

## 十三、结论

v2.0 股票分析引擎并不只是需要“股价数据”，而是需要一个多层股票数据底座：

1. 主数据层，解决“这只股票是谁”
2. 行情层，解决“它最近怎么走”
3. 大盘层，解决“市场环境如何”
4. 板块层，解决“它所在行业处在什么位置”
5. 财务层，解决“公司质量和估值如何”
6. 新闻层，解决“近期发生了什么”
7. 情绪层，解决“市场和投资者怎么看”
8. 筹码层，解决“持仓结构和压力位如何”

如果只保留最小可用集，v2.0 仍然可以运行，但会显著削弱：

- 行业位置感
- 系统性风险感知
- 事件驱动判断能力
- 情绪维度判断能力
- 支撑压力位精度

因此，从产品完整性和分析质量角度，推荐优先做满 P0，再逐步补齐 P1 与 P2。
