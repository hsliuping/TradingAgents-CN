# v2.0 股票数据需求清单

## 概述

本文档用于明确 TradingAgentsCN v2.0 股票分析引擎所需的数据范围、字段级要求、数据优先级以及库表映射关系。

目标不是描述“理论上分析股票可能需要什么数据”，而是回答以下三个工程问题：

1. v2.0 当前主工作流实际依赖哪些股票数据
2. 这些数据需要细化到哪些字段
3. 如果要做数据同步、数据建模、上线裁剪，哪些字段是必须的，哪些字段是增强项

本文档适用范围：

- v2.0 单股分析主工作流
- v2.0 批量分析复用链路
- v2.0 研究经理、交易员、风险经理依赖的上游股票分析数据

配套文档：

- [docs/design/v2.0/v2.0-stock-data-provider-mapping.md](docs/design/v2.0/v2.0-stock-data-provider-mapping.md)

不包含：

- 持仓分析专属账户字段
- 交易复盘专属订单字段
- ETF 专属基金字段

---

## 工作流视角的数据范围

v2.0 股票分析主工作流包含以下关键节点：

1. 大盘分析师
2. 板块分析师
3. 市场分析师
4. 基本面分析师
5. 新闻分析师
6. 社交媒体分析师
7. 看多研究员 / 看空研究员
8. 研究经理
9. 交易员
10. 风险分析师组
11. 风险经理

其中，前 6 个分析师节点直接消耗股票数据，研究经理还会委托筹码分布分析师补充判断。因此，v2.0 的股票数据需求可以拆分为 8 个数据域：

1. 股票主数据
2. 个股行情与技术面数据
3. 大盘 / 指数环境数据
4. 行业 / 板块数据
5. 基本面 / 财务数据
6. 新闻 / 公告数据
7. 社媒 / 情绪数据
8. 筹码分布数据

## 一、股票主数据

股票主数据用于工作流初始化、提示词变量注入、行业映射、市场识别、货币识别，以及后续所有分析节点的上下文构建。

### 1.1 必需字段

| 字段名 | 类型 | 必需 | 示例 | 说明 |
|---|---|---|---|---|
| code | string | 是 | 600519 | 6 位股票代码或统一主代码 |
| symbol | string | 否 | 600519.SH | 带交易所后缀代码，便于跨源兼容 |
| name | string | 是 | 贵州茅台 | 股票名称 |
| industry | string | 是 | 白酒 | 所属行业，用于板块分析和行业维度注入 |
| market | string | 是 | 主板 | 上市板块或市场层级 |
| source | string | 是 | tushare | 主数据来源 |
| area | string | 否 | 贵州 | 地域信息，可用于扩展分析 |
| list_date | string/date | 否 | 2001-08-27 | 上市日期 |
| current_price | number | 否 | 1688.00 | 备用当前价，主来源仍建议走行情表 |

### 1.2 建议补充字段

| 字段名 | 类型 | 必需 | 示例 | 说明 |
|---|---|---|---|---|
| is_st | bool | 否 | false | 是否 ST，可提前标记风险 |
| exchange | string | 否 | SSE | 交易所代码 |
| market_type | string | 否 | A股 | 市场大类 |
| currency_name | string | 否 | 人民币 | 计价货币名称 |
| currency_symbol | string | 否 | ¥ | 计价货币符号 |

### 1.3 主要用途

- 构造 company_name、industry、market_name、currency_name、currency_symbol 等系统变量
- 提供行业映射给板块分析师和研究经理
- 作为新闻、情绪、财务、行情等多类数据的统一关联键

## 三、大盘 / 指数环境数据

大盘分析师负责回答市场整体风险偏好、趋势状态和系统性风险，不依赖单只股票本身，而依赖指数和盘面数据。

### 3.1 指数走势字段

建议至少覆盖以下指数：

- 上证指数
- 深证成指
- 创业板指
- 沪深 300
- 中证 500

字段建议：

| 字段名 | 类型 | 必需 | 示例 | 说明 |
|---|---|---|---|---|
| index_code | string | 是 | 000300.SH | 指数代码 |
| index_name | string | 是 | 沪深300 | 指数名称 |
| trade_date | string/date | 是 | 2026-03-20 | 交易日 |
| close | number | 是 | 3898.21 | 收盘点位 |
| pct_chg | number | 是 | 0.86 | 当日涨跌幅 |
| chg_5d | number | 否 | 1.92 | 5 日涨跌幅 |
| chg_20d | number | 否 | 4.35 | 20 日涨跌幅 |
| volume | number | 否 | 325000000 | 成交量 |
| amount | number | 否 | 420000000000 | 成交额 |
| ma20 | number | 否 | 3840.22 | 20 日均线 |
| ma60 | number | 否 | 3772.11 | 60 日均线 |

### 3.2 市场宽度字段

|---|---|---|---|

| down_count | number | 是 | 下跌家数 |

### 3.3 市场环境字段

| 字段名 | 类型 | 必需 | 说明 |

| margin_buy | number | 否 | 融资买入额 |
| short_balance | number | 否 | 融券余额 |

### 3.5 QMT 模式差异

如果走 QMT 模式，则可接受字段范围收缩为：

- 指数趋势
- 市场扩散度
- 成交活跃度
- 风格切换
- 盘面结构

但以下字段不应作为硬依赖：

- 北向资金官方口径
- 两融官方口径
- 涨跌停官方统计
- 指数估值快照

| 字段名 | 类型 | 必需 | 说明 |
|---|---|---|---|
| event_type | string | 否 | 财报 / 公告 / 监管 / 行业 / 并购 / 产品 |

| 范围 | 必需 | 说明 |

## 八、筹码分布数据

筹码分布数据由研究经理委托的筹码分布分析师使用，主要用于判断获利盘压力、平均成本和区间集中度。

### 8.1 核心字段

| 字段名 | 类型 | 必需 | 说明 |
|---|---|---|---|
| code | string | 是 | 股票代码 |
| date | string/date | 是 | 分析日期 |
| source | string | 否 | 数据源 |
| profit_ratio | number | 是 | 获利比例 |
| avg_cost | number | 是 | 平均持仓成本 |
| cost_90_low | number | 是 | 90% 筹码区间下沿 |
| cost_90_high | number | 是 | 90% 筹码区间上沿 |
| concentration_90 | number | 否 | 90% 集中度 |
| cost_70_low | number | 是 | 70% 筹码区间下沿 |
| cost_70_high | number | 是 | 70% 筹码区间上沿 |
| concentration_70 | number | 否 | 70% 集中度 |

### 8.2 底层原始字段对照

如果使用 Tushare cyq_perf 口径，底层原始字段通常为：

| 原始字段 | 转换后字段 | 说明 |
|---|---|---|
| winner_rate | profit_ratio | 获利比例 |
| weight_avg | avg_cost | 加权平均成本 |
| cost_5pct | cost_90_low | 90% 区间下沿 |
| cost_95pct | cost_90_high | 90% 区间上沿 |
| cost_15pct | cost_70_low | 70% 区间下沿 |
| cost_85pct | cost_70_high | 70% 区间上沿 |

### 8.3 最小可用要求

至少需要：

- profit_ratio
- avg_cost
- cost_90_low
- cost_90_high
- cost_70_low
- cost_70_high

## 十三、结论

v2.0 股票分析引擎并不只是需要“股价数据”，而是需要一个多层股票数据底座：

1. 主数据层，解决“这只股票是谁”
2. 行情层，解决“它最近怎么走”
3. 大盘层，解决“市场环境如何”
4. 板块层，解决“它所在行业处在什么位置”
5. 财务层，解决“公司质量和估值如何”
6. 新闻层，解决“近期发生了什么”
7. 情绪层，解决“市场和投资者怎么看”
8. 筹码层，解决“持仓结构和压力位如何”

如果只保留最小可用集，v2.0 仍然可以运行，但会显著削弱：

- 行业位置感
- 系统性风险感知
- 事件驱动判断能力
- 情绪维度判断能力
- 支撑压力位精度

因此，从产品完整性和分析质量角度，推荐优先做满 P0，再逐步补齐 P1 与 P2。
