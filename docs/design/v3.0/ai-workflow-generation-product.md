## 1. 产品愿景

### 一句话描述

> **用户只需用自然语言描述分析需求，AI 自动设计并创建一套完整的多智能体分析流程——包括流程结构、每个角色的专属行为指令、以及缺失工具的自动补齐。**

### 产品定位

将「创建分析流程」从一项**需要理解系统架构的技术操作**，变为一次**与 AI 架构师的自然对话**。

```
                        ┌──────────────┐
  现在：技术操作          │  了解 Agent  │ → 选择节点 → 拖拽连线 → 配置提示词 → 绑定工具
                        └──────────────┘
                              门槛高，步骤多，容易出错

                        ┌──────────────┐
  未来：自然对话          │ "帮我创建    │ → AI 自动完成一切 → 用户确认 → 立即可用
                        │  可转债分析流" │
                        └──────────────┘
                              零门槛，一键完成
```

## 2. 目标用户与痛点

### 2.1 目标用户画像

| 用户类型 | 描述 | 占比 |
| -------- | ---- | ---- |
| 📊 投资者/交易员 | 有明确的分析需求，但不了解系统的 Agent 和工具体系 | 60% |
| 🔧 高级用户 | 了解系统能力，但不想花时间手动搭建流程 | 25% |
| 🆕 新用户 | 刚接触系统，需要快速体验产品价值 | 15% |

### 2.2 用户痛点

| # | 痛点 | 严重程度 | 说明 |
| - | ---- | -------- | ---- |
| 1 | **不知道有哪些 Agent 可用** | 🔴 高 | 系统有 33+ 个 Agent，用户根本记不住也不理解 |
| 2 | **不知道怎么设计流程拓扑** | 🔴 高 | 并行、辩论、合并等概念对非技术用户很陌生 |
| 3 | **不知道要配置什么提示词** | 🟡 中 | 每个 Agent 都有提示词模板，新场景需要定制但用户不会写 |
| 4 | **缺少的工具不知道怎么补** | 🟡 中 | 遇到特殊分析需求时缺少对应工具，用户束手无策 |
| 5 | **创建完不知道好不好用** | 🟡 中 | 缺少迭代优化机制，只能反复手动调整 |

### 2.3 用户的心声

> *「我就想分析一下可转债，为什么要我去学什么节点类型、Agent 配置、提示词模板？能不能直接告诉系统我要什么，它帮我搞定？」*

## 3. 核心价值主张

### 3.1 解决什么问题

| 之前（手动创建） | 之后（AI 架构师） |
| ---------------- | ----------------- |
| 需要了解 33+ 个 Agent 的能力 | 用自然语言描述需求即可 |
| 手动设计节点拓扑结构 | AI 自动设计最优流程结构 |
| 手动编写每个 Agent 的提示词 | AI 评估哪些需要定制，自动生成 |
| 缺少工具时束手无策 | AI 自动检测并创建缺失工具 |
| 创建完毕没有优化途径 | 运行后可对话式迭代优化 |
| 整个过程 30-60 分钟 | 对话 2-3 轮，5 分钟完成 |

### 3.2 产品差异化：五大独创能力

#### 🧠 能力一：Agent 角色重塑

同一个「市场分析师」在不同流程中可以扮演完全不同的角色，无需创建新 Agent：

| 流程 | 市场分析师的角色 | 自动生成 |
| ---- | --------------- | -------- |
| A 股分析流 | 股票市场技术分析师 | 使用默认提示词 ✅ |
| 可转债分析流 | 可转债市场分析师 | 自动生成专属提示词 ⚠️ |
| ETF 筛选流 | ETF 市场趋势分析师 | 自动生成专属提示词 ⚠️ |

**用户无感知**：用户不需要理解「提示词」这个概念，AI 自动判断并处理。

#### 🔧 能力二：工具自动补齐

当用户的分析需求涉及系统中尚不存在的计算工具时，AI 会自动创建：

```
用户：帮我创建一个可转债分析流程，重点看溢价率
AI  ：检测到缺少「可转债溢价率计算器」，将自动创建 ✅
```

#### 🔄 能力三：闭环迭代优化

创建不是终点，用户可以持续优化：

```
创建 → 运行 → 查看结果 → 提反馈 → AI 自动调整 → 再运行 → ...
```

#### 🏗️ 能力四：三层配置模型 — 精细粒度的按需覆盖

工具绑定和提示词支持**三层优先级**，同一个 Agent 在不同节点可以拥有完全不同的配置：

```
Agent 定义层（保底默认）
      ↓ 可被覆盖
Workflow 层（流程专属）
      ↓ 可被覆盖
Node 层（节点专属，最高优先级）
```

**实际意义**：`market_analyst` 在「可转债价格分析节点」使用溢价率工具 + 溢价率分析提示词；同一 `market_analyst` 在「流动性分析节点」使用成交量工具 + 流动性提示词——**两个节点完全独立配置，互不干扰**。

AI 工作流架构师在生成蓝图时自动指定每个节点的工具需求，`confirm_and_create()` 时自动写入节点级绑定记录。

#### 🤖 能力五：UniversalAgent — 无代码新角色创建

AI 可以创建真正**全新的 Agent 角色**，而不仅仅是为现有 Agent 换提示词——且完全无需编写任何 Python 代码：

```
用户：帮我创建可转债分析流程
AI  ：检测到需要「可转债条款分析师」（系统中不存在）
      → 自动写入 agent_configs（角色定义 + 输出字段）
      → 生成节点专属提示词（prompt_templates）
      → 运行时 AgentFactory 自动创建 UniversalAgent 实例
      → 流程正常运行 ✅
```

**技术保证**：`UniversalAgent` 是完全由数据库配置驱动的通用 Agent 类，零硬编码业务逻辑，可承载 80-95% 的分析型 Agent 角色（符合「单一职责」原则：拿数据 → 分析 → 输出）。

## 4. 用户旅程

### 4.1 核心流程（Happy Path）

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  ① 用户点击「新建分析流程」                                       │
│     └→ 弹出创建面板，看到两个选项：「模板创建」和「AI 智能创建」    │
│                                                                 │
│  ② 用户选择「AI 智能创建」                                       │
│     └→ 进入全屏对话界面                                          │
│                                                                 │
│  ③ 用户输入需求（自然语言）                                       │
│     例："帮我创建一个可转债分析流程，重点看转股溢价率和正股基本面"    │
│                                                                 │
│  ④ AI 返回方案草案                                               │
│     ├── 📊 流程结构（哪些角色、怎么协作）                         │
│     ├── 📋 智能评估（哪些角色需要专门定制）                       │
│     └── 🔧 工具检查（缺什么工具、需要创建什么）                   │
│                                                                 │
│  ⑤ 用户选择                                                     │
│     ├── 继续修改 → 回到 ③（用户可反复调整）                      │
│     ├── 确认创建 → 进入 ⑥                                       │
│     └── 关闭（自动保存为草稿，下次继续）                          │
│                                                                 │
│  ⑥ AI 自动创建                                                   │
│     ├── 生成需要定制的提示词                                      │
│     ├── 创建缺失的工具                                           │
│     └── 保存工作流定义                                           │
│     全程显示实时进度                                              │
│                                                                 │
│  ⑦ 创建完成                                                     │
│     ├── 显示创建报告（创建了什么、用了什么默认的）                 │
│     └── 跳转到流程编辑器（用户可进一步微调）                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

### 4.2 迭代优化流程

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  ① 用户运行已创建的工作流，查看分析结果                            │
│                                                                 │
│  ② 用户发现问题                                                  │
│     例："市场分析的部分对可转债条款分析不够深入"                     │
│                                                                 │
│  ③ 用户在工作流列表中点击「AI 优化」                               │
│     └→ 打开优化对话界面，加载历史对话记录                          │
│                                                                 │
│  ④ 用户输入改进意见                                               │
│                                                                 │
│  ⑤ AI 返回优化建议                                               │
│     ├── 结构调整（增/删节点、修改连接）                            │
│     ├── 提示词调整（修改角色定位）                                 │
│     └── 工具调整（补充缺失工具）                                   │
│                                                                 │
│  ⑥ 用户确认 → AI 自动应用修改                                    │
│                                                                 │
│  ⑦ 用户再次运行 → 效果改善 → 继续优化或满意为止                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.3 草稿恢复流程

用户可以随时中断创建过程，下次回来继续：

- 对话进行中关闭窗口 → 会话自动保存为**草稿**
- 下次进入工作流页面 → 页面顶部显示**未完成的草稿卡片**
- 点击「继续」→ 恢复到上次的对话状态

## 6. 交互设计要点

### 6.1 入口设计

在「新建分析流程」对话框中，增加 **Tab 切换**：

| Tab | 说明 |
| --- | ---- |
| 📋 模板创建 | 现有功能，选模板 → 输入名称 → 创建 |
| 🤖 AI 智能创建 | 新功能，进入全屏对话界面 |

### 6.2 全屏对话界面

选择「AI 智能创建」后，切换为**全屏对话界面**（参考智能助手页面风格）：

- **顶部**：标题「🤖 AI 工作流架构师」 + 关闭按钮
- **中间**：对话气泡区域（AI 消息 / 用户消息 交替展示）
- **底部**：输入框 + 发送按钮 + 「返回模板创建」 + 「✅ 确认创建」
- **AI 消息特殊排版**：
  - 📊 方案草案 — 层次化展示流程结构
  - 📋 提示词评估 — 表格展示（Agent | ✅默认 / ⚠️定制 | 说明）
  - 🔧 工具检查 — 列表展示缺失工具

### 6.3 创建进度界面

用户点击「确认创建」后，对话区域底部显示实时进度：

```
⏳ 正在创建工作流...

  ✅ 蓝图生成完成
  ⏳ 正在生成提示词 (3/4)
     ├── ✅ 市场分析师 提示词已创建
     ├── ✅ 基本面分析师 提示词已创建
     ├── ⏳ 交易员 提示词生成中...
     └── ⬜ 风险管理 待生成
  ⬜ 工具创建
     └── ⬜ 可转债溢价率计算器
  ⬜ 工作流保存
```

### 6.4 优化入口

在工作流列表中，AI 创建的工作流显示 `🤖 AI 创建` 标签和「AI 优化」按钮。

## 7. 用户场景示例

### 场景 1：可转债分析流（中等复杂度）

| 步骤 | 用户操作 | 系统响应 |
| ---- | -------- | -------- |
| 1 | 输入「帮我创建一个可转债分析流程，重点看转股溢价率和正股基本面」 | AI 设计 3 阶段方案（并行分析 → 辩论 → 决策），评估 4 个 Agent 需要定制提示词，建议创建 1 个新工具 |
| 2 | 点击「确认创建」 | 自动生成 4 套专属提示词 + 1 个溢价率计算器 + 工作流定义 |
| 3 | 跳转到编辑器，运行分析 | 生成可转债分析报告 |
| 4 | 反馈「条款分析不够深入」 | AI 建议增加条款分析节点，更新提示词 |

**耗时**：约 5 分钟（对话 2 轮 + 等待创建）
**成本**：约 ¥0.25-0.40

### 场景 2：标准 A 股分析流（简单）

| 步骤 | 用户操作 | 系统响应 |
| ---- | -------- | -------- |
| 1 | 输入「创建一个标准的 A 股分析流」 | AI 设计标准方案，评估所有 Agent 默认提示词足够 ✅，无需创建新工具 |
| 2 | 点击「确认创建」 | 直接生成工作流定义（无需额外创建提示词或工具） |

**耗时**：约 2 分钟
**成本**：约 ¥0.10-0.15

### 场景 3：多市场对比分析流（复杂）

| 步骤 | 用户操作 | 系统响应 |
| ---- | -------- | -------- |
| 1 | 输入「创建一个同时分析 A 股和港股的对比分析流程」 | AI 设计双市场并行分析方案，评估多个 Agent 需要定制（港股部分），建议创建 2 个新工具 |
| 2 | 修改「加上汇率风险分析」 | AI 调整方案，增加汇率分析节点 |
| 3 | 点击「确认创建」 | 生成完整流程 + 专属提示词 + 新工具 |

**耗时**：约 8 分钟（3 轮对话）
**成本**：约 ¥0.30-0.40

## 8. 成功指标（KPI）

### 8.1 核心指标

| 指标 | 目标值 | 衡量方式 |
| ---- | ------ | -------- |
| **AI 创建流程占比** | 上线 1 个月后 ≥ 40% | AI 创建数 / 总创建数 |

| 指标 | 目标值 | 说明 |

| **重复使用率** | ≥ 60% | 使用过 AI 创建后，下次还使用 AI 创建的比例 |

## 9. 运营成本

### 9.1 单次使用成本

| 场景 | AI 成本 | 说明 |
| ---- | ------- | ---- |
| 简单流程（默认提示词足够） | ¥0.10 - 0.15 | 2 轮对话 + 结构生成 |
| 中等流程（需定制提示词） | ¥0.15 - 0.25 | + 4 个提示词生成 |
| 复杂流程（定制 + 新工具） | ¥0.25 - 0.40 | + 工具代码自动生成 |
| 每轮迭代优化 | ¥0.10 - 0.20 | 反馈 + 方案调整 |

### 9.2 成本对比

| 操作 | AI 成本 | 说明 |
| ---- | ------- | ---- |
| 创建 1 个工作流 | ¥0.10 - 0.40 | **本功能** |
| 创建 1 个 Skill（已上线） | ¥0.02 - 0.10 | 代码生成 + 验证 |
| 运行 1 次分析（多 Agent） | ¥0.50 - 2.00 | 多 Agent 协作分析 |

> 💡 **结论**：AI 创建一个工作流的成本 < 运行一次分析的成本。对用户来说，用 ¥0.3 换来的是节省 30-60 分钟的手动配置时间。

### A.2 与 OpenClaw 的深度对比

OpenClaw 是目前最接近的同类系统——一个支持 AI 自动生成 Skill 的助手网关平台，拥有 ClawHub 社区市场。以下从多个维度进行对比。

#### 核心定位差异

| 维度 | OpenClaw | 我们（AI 工作流架构师） |
| ---- | -------- | ---------------------- |
| **本质** | AI 助手网关 + Skill 插件平台 | 金融多智能体工作流生成引擎 |
| **目标** | 给单个 AI 助手装上各种工具 | 编排多个专业 Agent 协作分析 |
| **领域** | 通用场景（搜索、文件、API 等） | 金融分析垂直领域（33+ Agent、100+ 工具） |
| **协作拓扑** | 单 AI + 多工具 | 多 Agent 有向图（并行/辩论/汇总） |

#### Skill 生成与验证机制对比

| 维度 | OpenClaw | 我们 |
| ---- | -------- | ---- |
| **Skill 生成方式** | AI 自动生成 | AI 自动生成 |
| **何时验证** | 运行后（Self-Auditing） | 运行前（沙盒测试 + 评分） |
| **静态分析** | 可选（skill-evaluator 脚本） | ✅ 必经步骤（语法/安全/依赖） |
| **沙盒执行** | ❌ 无（直接在主环境运行） | ✅ 子进程隔离执行 |
| **质量评分** | 可选（25 指标 / 100 分制） | ✅ 必经步骤（Judge LLM 0-10 分） |
| **自动迭代** | 运行失败 → AI 修复 → 再试 | 评分不过 → 带反馈重生成（最多 3 轮） |
| **运行时监控** | ✅ Moltron 提供完整 APM | ❌ 目前没有（v3.2 规划） |
| **版本回滚** | ✅ Moltron 的 Time-Machine | ❌ 目前没有（v3.2 规划） |
| **Skill 沉淀** | ClawHub 社区共享 | 仅本地 MongoDB |
| **验证是否强制** | 全部可选 | 静态+沙盒+评分为强制流程 |

#### OpenClaw 验证机制三层架构

| 层级 | 机制 | 说明 |
| ---- | ---- | ---- |
| **第一层：原生** | 试错迭代 | 生成 → 执行 → 失败则 AI 修复 → 再试，无预验证 |
| **第二层：Moltron.ai** | 运行时自审计 | Self-Auditing（性能追踪）、Time-Machine（版本回滚）、Continuous Improvement（自动优化）、OpenTelemetry Dashboard |
| **第三层：社区工具** | 发布前评审 | skill-evaluator（8 大类 25 指标 100 分制）+ SkillLens（安全扫描），但为可选流程 |

#### 验证哲学差异

> - **OpenClaw**：「**宽进严出**」—— 先跑起来，事后追踪，不好用就回滚改进。更敏捷但风险更高。
> - **我们**：「**严进宽出**」—— 未通过预检的 Skill 不会上线。更安全但可能过度保守。

#### 我们的独有优势

1. **多 Agent 协作拓扑** — 并行分析、多空辩论、风险评估、基金经理决策，OpenClaw 架构上不支持
2. **提示词评估与定制** — 同一 Agent 在不同工作流中自动获得不同行为指令，OpenClaw 无此概念
3. **全局缺口分析** — 不仅分析 Skill 够不够，还评估 Agent 搭配、提示词匹配、流程结构合理性
4. **金融垂直深度** — 33+ 专业金融 Agent、100+ 金融数据工具，非通用平台可比
5. **三层配置模型** — 工具和提示词均支持 Node > Workflow > Agent 三层优先级，同一 Agent 在不同节点可有完全不同的配置；OpenClaw 工具绑定是全局的，无法按节点精细化
6. **UniversalAgent 无代码扩展** — AI 可在零代码的情况下创建全新 Agent 角色，写入数据库配置即可运行；AgentFactory 自动回落到 UniversalAgent，扩展成本为零

2. **版本回滚**（已纳入 v3.2 路线图）— 工作流和 Skill 的版本历史，出问题可回退
3. **社区共享**（待评估）— ClawHub 的飞轮效应：用户越多 → Skill 越丰富 → 体验越好
