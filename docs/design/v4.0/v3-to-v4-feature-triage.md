# 智能助手 v4.0 设想：v3.0 功能到 v4.0 的取舍与迁移判断

## 📋 文档信息

| 项目 | 内容 |
| --- | --- |
| 版本 | v4.0 Concept |
| 状态 | 设想 / 草案 |
| 日期 | 2026-03-06 |
| 目标 | 对 `docs/design/v3.0/` 中尚未上线的功能方案做一次面向 v4.0 的价值判断，明确哪些应继承、哪些应重构、哪些应弱化 |

---

## 1. 背景

`v3.0` 目录中积累了大量功能设想，其中一部分已经接近实现，另一部分仍停留在设计阶段。

这些方案并不是“有没有技术价值”的问题，而是要重新回答：

- 对 `v4.0` 的产品主线有没有帮助
- 它更像产品价值，还是平台能力
- 它会不会把系统带向失控、自增长或过度平台化

结合前面已经收敛出的 `v4.0` 方向，本次判断主要围绕以下主线：

- 长期跟踪
- 过程闭环
- 用户私有研究资产沉淀
- 可信边界与主权控制
- 强入口能力与长期留存能力的结合

---

## 2. 判断标准

### 2.1 优先保留什么

优先保留那些能够直接增强以下能力的设计：

- 用户入口价值
- 选股 / 分析 / 跟踪 / 复盘之间的连接能力
- 长期研究资产承接能力
- 系统级通知、记忆、数据承接能力
- AI / 系统 / 用户边界的清晰化

### 2.2 优先弱化什么

优先弱化那些容易把产品带向以下方向的设计：

- AI 工作流 / Agent 构建平台
- Skill 自动生长平台
- 多通道 Bot 平台化扩张
- 黑盒化自动扩张与自动接管

一句话概括：

**v4.0 要留下“入口、闭环、沉淀、通知、边界”，弱化“自动造系统、自动长技能、平台化扩张”。**

---

## 3. 总体结论

### 3.1 直接继承到 v4.0 主线的方向

以下能力与 `v4.0` 的主线高度一致，应继续保留并纳入后续设计参考：

- 智能助手作为统一入口与过程协调层
- 智能筛选作为选股入口与候选发现层
- 统一通知架构
- 数据架构与资产承接底座
- 确认机制、意图路由、诚实边界

### 3.2 需要重构后继承的方向

以下能力有价值，但不能直接沿用 `v3.0` 的叙事方式：

- Skill 缺口感知
- MCP 支持
- 回测服务
- ETF / 北交所支持
- QMT 数据接入
- 外部 Skill 生态参考接入

### 3.3 应明显弱化或后置的方向

以下能力更偏平台化、自增长或高复杂度系统建设，不应成为 `v4.0` 的近期主轴：

- AI 工作流架构师
- Skill 自动生成系统
- Skill 自动生成 UI 优化
- 以 MCP Server / Gateway 为中心的产品扩张

---

## 4. 分组判断

### 4.1 强保留：应进入 v4.0 主线参考

#### `intelligent-assistant.md`

价值判断：**强保留**。

原因：

- 它本质上是统一入口、意图路由和系统协调层
- 能承接分析、报告、计划、复盘等多类动作
- “先确认再执行”与 `v4.0` 的主权边界高度一致

迁移建议：

- 从“全能操作员”重构为“投研工作台入口 + 过程协调器 + 长期陪伴助手”

#### `intelligent-screening.md`

价值判断：**强保留**。

原因：

- 它解决的是最强前台入口问题：选股
- 两阶段流程、结构化结果卡、后续分析入口都很适合 `v4.0`
- 能自然衔接候选池、跟踪对象与研究起点

迁移建议：

- 不要做成独立能力孤岛，应重构为“选股入口层 / 候选发现层”

#### `notification-architecture.md`

价值判断：**强保留**。

原因：

- 长期跟踪、任务完成、计划提醒、复盘提醒都依赖统一通知体系
- 是闭环能力的重要基础设施

迁移建议：

- 继续作为统一通知中心，不需要大改方向

#### `data-architecture-plan.md`

价值判断：**强保留**。

原因：

- `v4.0` 的知识底座、研究资产、事实/观点/规则分层都需要数据承接基础
- 它不是前台功能，但决定后面很多能力能不能落下去

迁移建议：

- 作为底层蓝图保留，后续按 `v4.0` 的资产结构重新裁剪

#### `intelligent-assistant-test-cases.md`

价值判断：**保留**。

原因：

- 它沉淀了确认机制、意图消歧、诚实原则、角色差异等关键测试思路

迁移建议：

- 升级为 `v4.0` 的场景验证集，而不是只面向 QQ 机器人

### 4.2 保留但重定位：有价值，但不能直接照搬

#### `skill-gap-perception.md`

价值判断：**保留但重定位**。

原因：

- “AI 发现能力缺口，用户决定是否处理”这个思路很契合受控成长
- 但不能顺着它走向自动长 Skill 的产品叙事

迁移建议：

- 改为“系统能力缺口发现 / 产品迭代输入 / 管理员决策台”

#### `mcp-support.md`

价值判断：**保留但重定位**。

原因：

- MCP 是能力接入方式，不是产品价值本身

迁移建议：

- 保留 `MCP Client` 的集成价值
- 弱化 `MCP Server` 的产品中心地位

#### `backtest-service.md`

价值判断：**保留但后移**。

原因：

- 回测与计划验证、规则验证、复盘增强相关
- 但不是当前最强入口，也不是最优先主线

迁移建议：

- 不纳入 v4.0 主线，整体后移到 v5.0 的“投资系统 / 计划验证 / 复盘增强”链路里

#### `beijing-exchange-etf-support.md`

价值判断：**保留但作为覆盖能力**。

原因：

- ETF 很适合长期投资用户，价值较高
- 北交所更多是市场覆盖完整性问题

迁移建议：

- 作为标的覆盖能力建设，不作为产品主叙事

#### `qmt-support.md`

价值判断：**保留但收敛边界**。

原因：

- 对持仓辅助和真实投资者上下文有帮助
- 但容易把产品拉向执行与交易中心

迁移建议：

- 只保留数据接入与账户上下文价值，避免走向自动交易叙事

#### `clawhub-integration.md`

价值判断：**轻量保留**。

原因：

- 外部生态可提供参考与启发
- 但核心能力不能建立在不受控的外部 Skill 生态上

迁移建议：

- 维持参考型利用与轻桥接，不应成为主线路线

### 4.3 应弱化或内部化：不宜做成 v4.0 主功能

#### `ai-workflow-generation.md` / `ai-workflow-generation-product.md`

价值判断：**明显弱化**。

原因：

- 方向过于平台化，更像“让 AI 帮用户造工作流系统”
- 不是当前用户最核心、最迫切的价值点

迁移建议：

- 只保留其中关于三层配置、能力重塑的底层思想
- 不要把“AI 工作流架构师”放到 `v4.0` 前台主功能里

#### `skill-generation-system.md`

价值判断：**强烈建议后置**。

原因：

- 成本高、复杂度高、验证难、安全风险大
- 与 `v4.0` 当前强调的“受控成长”边界不完全一致

迁移建议：

- 如果保留，应优先作为内部能力建设或管理员辅助工具

#### `skill-generation-ui-optimization.md`

价值判断：**随主功能一起后置**。

原因：

- 它依赖 Skill 自动生成系统本身
- 主系统不优先，这部分 UI 也不该先行

#### `implementation-plan.md`

价值判断：**历史参考即可**。

原因：

- 它更像阶段性执行计划，而不是需要继承的产品能力

---

## 5. 最值得继承的 v3.0 思想

本轮回看后，最值得进入 `v4.0` 的不是某几个孤立功能，而是以下底层原则：

- **先确认再执行**：高代价动作、模糊需求、正式资产沉淀都应先确认
- **意图驱动路由**：统一入口必须理解用户是来选股、分析、跟踪、计划还是复盘
- **统一通知入口**：闭环能力必须靠统一的提醒与反馈系统支撑
- **多轮记忆升级为过程记忆**：从“记住聊天”升级为“记住投研过程和研究资产”
- **三层配置思路可继承**：保留配置化思想，但不要强绑定到 AI 自动造工作流

---

## 6. 最应弱化的 v3.0 倾向

从 `v4.0` 角度看，以下倾向最值得主动收敛：

- 弱化“AI 自动造工作流”
- 弱化“AI 自动长 Skill”
- 弱化“多通道 Bot 化就是主产品形态”
- 弱化“平台生态扩张优先于用户闭环价值”

这些方向不是完全没用，而是更适合：

- 内部化
- 后置化
- 收敛到底层能力

而不适合作为近期面向用户的主叙事。

---

## 7. 面向 v4.0 的优先级建议

### P0：最值得继续投入的能力

- 智能助手重构为统一投研入口
- 智能筛选重构为选股入口层
- 统一通知架构
- 数据架构与资产沉淀底座
- 确认机制、意图路由、可信边界

### P1：可保留，但不要喧宾夺主

- Skill 缺口感知
- ETF / 北交所等覆盖能力
- MCP Client 外部能力接入
- QMT 数据接入
- 回测能力

### P2：可内部化 / 后置化

- AI 工作流架构师
- Skill 自动生成系统
- Skill 生成 UI
- MCP Server 平台化输出
- 外部 Skill 生态化接入

---

## 8. 本文结论

如果把这次判断压缩成一句话：

**v3.0 里最值得带入 v4.0 的，是“助手入口化、选股前台化、通知统一化、数据资产化、边界清晰化”；最应该弱化的，是“让系统自动造工作流、自动长 Skill、向平台生态扩张”。**

这份判断适合作为后续 `v4.0` 路线图、原型优先级与能力迁移表的参考基础。
