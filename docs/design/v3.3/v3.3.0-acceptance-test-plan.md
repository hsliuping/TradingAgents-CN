# TradingAgents-CN v3.3.0 验收测试计划

## 文档目的

本计划用于 `v3.3.0` 小版本验收。

该版本聚焦“开放集成”，目标不是服务所有普通用户，而是验证产品能否以受控方式被外部系统调用。

## 版本定位

- 版本主题：开放集成版
- 目标用户：开发者、外部集成方、定向客户
- 发布形态：Beta 或定向开放
- 核心目标：提供稳定、可控、可理解的 MCP 对外能力

## 纳入范围

1. MCP Server 入口。
2. 6 个 MCP 工具。
3. API Key 认证。
4. 每日配额控制。
5. 基础集成文档与示例。

## 不纳入范围

1. 把 MCP 作为普通用户主入口。
2. MCP 数据源治理完整扩展。
3. 飞书、钉钉等多平台扩张。
4. 回测服务。

## 验收重点

1. 集成方能否快速接通最核心的 MCP 工具。
2. 认证、配额、错误语义是否稳定一致。
3. 文档是否足以支撑定向接入，而不是只能靠口头说明。

## 核心验收场景

### 场景 A：认证与鉴权

1. 使用有效 API Key 调用工具。
2. 使用无效 API Key 调用工具。
3. 使用超限账号调用工具。

预期结果：

1. 有效请求成功。
2. 无效请求被明确拒绝。
3. 超限请求能返回清晰限制信息。

### 场景 B：6 个 MCP 工具

1. `analyze_stock`
2. `get_report`
3. `chat_with_assistant`
4. `list_workflows`
5. `screen_stocks`
6. `get_market_overview`

预期结果：

1. 每个工具都能在标准输入下稳定返回。
2. 错误场景下返回结构一致。
3. 工具之间的语义边界清晰，不需要调用方猜测。

### 场景 C：文档与示例

1. 按文档完成一次最小接入。
2. 按示例调用至少两个不同工具。

预期结果：

1. 不依赖内部人员手把手指导也能完成基础接入。
2. 文档与实际行为一致。

## 入口条件

1. 已准备测试用 API Key、配额策略和标准接入脚本。
2. 6 个工具对应的底层服务在测试环境可用。
3. 接入文档和示例已完成第一版。

## 退出条件

1. 鉴权、配额、6 个核心工具全部通过验收。
2. 至少完成一次“按文档独立接入”的验证。
3. 不存在阻塞级错误语义混乱、权限绕过或严重不一致问题。

## 风险提示

1. MCP 虽然不是普通用户主链路，但一旦开放，兼容性和错误语义会变成长期成本。
2. 如果文档与实现不一致，会显著放大支持成本。
