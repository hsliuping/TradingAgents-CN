# TradingAgents-CN v3.4.0 验收测试计划

## 文档目的

本计划用于 `v3.4.0` 小版本验收。

该版本不是面向所有用户的公开发布，而是验证 Agent / Workflow / Skill 平台能力是否具备内部提效或小范围客户试点价值。

## 版本定位

- 版本主题：Agent 生产力内测版
- 目标用户：内部团队、小范围客户、管理员
- 发布形态：Private Preview
- 核心目标：验证构建 Agent / Workflow / Skill 的生产效率价值是否成立

## 纳入范围

1. AI 工作流架构师。
2. Agent 工坊。
3. Skill 自动生成系统。

## 不纳入范围

1. 面向所有普通用户公开。
2. 发布审批、灰度发布、生产反馈自动回流等未完成治理能力。
3. 回测服务。

## 验收重点

1. 这些能力是否真的提升内部构建效率，而不是只展示“能生成”。
2. 复杂链路是否可调试、可评估、可回滚到人工介入。
3. 权限边界是否清楚，避免误开放给普通用户。

## 核心验收场景

### 场景 A：AI 工作流架构师

1. 启动会话。
2. 多轮澄清需求。
3. 确认并创建工作流。
4. 基于反馈执行优化。
5. 发布工作流。

预期结果：

1. 从需求到工作流草案链路可跑通。
2. 优化后差异可解释。
3. 发布动作不会破坏已有可用配置。

### 场景 B：Agent 工坊

1. 启动工坊会话。
2. 完成规格澄清与预览。
3. 发起能力快照与缺口分析。
4. 构建版本并审阅 Prompt。
5. 执行 debug、evaluate、iterate、publish。

预期结果：

1. 五步工作台链路完整。
2. 评估和迭代不只是形式接口，而能产生可理解结果。
3. 发布后版本状态切换正确。

### 场景 C：Skill 自动生成

1. 输入需求。
2. 生成代码。
3. 静态校验。
4. 沙箱执行。
5. 输出评估。
6. 迭代后保存。

预期结果：

1. 6 阶段管线完整。
2. 失败原因能被定位和反馈。
3. 通过的 Skill 可被注册和复用。

### 场景 D：权限与运维边界

1. 使用普通用户账号访问相关入口。
2. 使用管理员或内测账号访问相关入口。

预期结果：

1. 权限边界清楚。
2. 不会误对所有用户公开平台能力。

## 入口条件

1. 相关页面与 API 已限定在测试或管理员范围内。
2. 已准备标准试用任务与可回收测试数据。
3. 支持人员能查看日志、调试结果与评估记录。

## 退出条件

1. 三大平台能力的核心链路可由内部团队独立走通。
2. 没有阻塞级权限问题、严重配置污染或结果不可追踪问题。
3. 验收结论必须区分“可内测”与“可公测”，默认不直接进入公开发布。

## 风险提示

1. 这类平台能力容易让团队高估成熟度，必须坚持内测口径。
2. 如果审批、灰度、生产反馈闭环未补齐，不建议提前承诺为正式公开能力。
