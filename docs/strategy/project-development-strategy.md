## 一、项目现状

### 1.1 核心数据

| 指标 | 数值 | 说明 |
|------|------|------|
| GitHub Star | 30k+ | 主要由 v1.0 开源版吸引 |
| 注册用户 | 1万+ | v2.0 版本 |
| 赞助用户 | ~100人 | 转化率约 1% |
| 开发团队 | 1人 | 项目所有者独立开发 |
| v3.0 状态 | 开发完成 | 准备发布 |

### 1.2 转化漏斗

```
30k star（GitHub 关注）
  → 1万注册（3.3% 转化率，偏低）
    → 100赞助（1% 转化率，开源项目典型水平）
```

**问题诊断**：
- star → 注册转化率偏低，说明很多人 star 但未深入使用
- 注册 → 赞助转化率正常偏低，因为"赞助"是自愿付费
- 核心问题：**赞助模式天然转化率低**，需要转向"授权许可"模式

### 1.3 核心优势

1. **社区影响力**：30k+ star，技术品牌认知度高
2. **技术能力**：AI + 金融领域的深度技术积累
3. **用户基础**：1万注册用户，100 付费意愿用户
4. **产品成熟度**：v3.0 已开发完成，功能完整

### 1.4 核心瓶颈

1. **合规顾虑**：担心股票分析的法律法规边界，不敢商业化
2. **人手不足**：一人开发，迭代速度受限
3. **盗版问题**：v1.0 被其他公司未授权商业使用
4. **变现困难**：赞助模式转化率低，缺乏稳定的收入来源

## 二、合规边界分析

### 2.1 产品定位

TradingAgents-CN 是 **AI 驱动的股票分析工具**，不是投资顾问服务。

| 荐股（违规） | 分析工具（合规） |
|---|---|
| "买入XX股票" | "XX股票的财务指标如下" |
| "这只股票会涨" | "AI agent 从多维度分析的结果" |
| 承诺收益 | 仅供参考，不构成投资建议 |
| 代客理财 | 用户自主决策 |

**结论**：项目定位合法合规，风险可控。

### 2.2 合规动作清单

| 优先级 | 动作 | 说明 |
|--------|------|------|
| P0 | 添加免责声明 | 产品全界面加固定免责声明 |
| P0 | 分析报告底部加免责声明 | "不构成投资建议" |
| P0 | 用户协议明确"工具"属性 | 法律层面界定 |
| P1 | 咨询证券律师 | 获取专业合规意见 |
| P1 | 注册公司主体 | 以公司名义运营 |
| P2 | 申请软件著作权 | 侵权时的直接证据 |
| P2 | 注册商标 | 保护品牌 |

### 2.3 免责声明模板

```

## 三、商业模式设计：逐步开源

### 3.1 策略概述

采用 **逐步开源（滚动开源）** 策略：

```
v1.0 → 已开源（引流，建立技术品牌）
v2.0 → 现在开源（完整功能，建立用户习惯）
v3.0 → 付费版（专业功能，核心收入）
v4.0 → 开发完成后，v3.0 开源
v5.0 → 开发完成后，v4.0 开源
...（滚动循环）
```

**核心原则**：当新版本稳定运行 3-6 个月后，上一版本开源。不承诺具体时间。

### 3.2 业界对标

| 项目 | 开源策略 | 效果 |
|------|---------|------|
| Ghostscript | GPL 版本滞后发布，商业版实时 | 成功运营 30 年 |
| IntelliJ IDEA | Community 版开源，Ultimate 付费 | JetBrains 年营收 $10亿+ |
| MySQL | 社区版 GPL，企业版付费 | Oracle 收购价 $74亿 |
| Qt | LGPL 开源（旧版本），商业许可（最新） | 双轨制运行 20 年 |

### 3.3 策略优势

1. **持续引流**：每次开源旧版本 = 一次免费营销
2. **付费动力清晰**：付费 = 用最新版 + 专业功能
3. **社区贡献回流**：开源版 bug 修复可 cherry-pick 到当前版本
4. **对抗 Fork**：持续开源新版本，别人 Fork 旧版无意义
5. **合规透明**：开源代码可审查，证明是"工具"不是"荐股"

### 3.4 版本功能分层

| 功能 | v2.0 开源版 | v3.0 Pro |
|------|-----------|----------|
| 单股分析 | ✅ | ✅ |

| 数据源配置 | ✅ | ✅ |

| 定时分析 | ✅ | ✅（增强版） |
| 邮件通知 | ✅ | ✅ + 渠道推送 |
| AI 工作流设计器 | ❌ | ✅ |
| 复盘研究 | ❌ | ✅ |
| 持仓研究 | ❌ | ✅ |
| Skill 系统 / MCP | ❌ | ✅ |
| 智能助手 | ❌ | ✅ |

| 持续更新 + 技术支持 | ❌ | ✅ |

**关键**：每个新版本必须有"必须升级"的杀手锏功能。

## 四、v2.0 开源策略

### 4.1 开源范围

**全部开源，包括高级功能**。

理由：
1. "半开源"会损害声誉，被批评"假开源"
2. v2.0 高级功能在 v3.0 面前只是"基础功能"
3. 开源高级功能 = 最好的引流（让用户体验价值）
4. 藏着不放 = 得不到任何好处

### 4.2 开源前清理清单

**需要清理的**：
- 积分系统 / 捐助验证逻辑
- 授权码验证
- 付费相关的 UI 和路由
- 任何与"捐助换积分"相关的代码
- 私有 API Key、密钥
- 客户定制代码（京东云合作版专属逻辑）
- 内部文档（设计文档、商业计划）
- commit history 中的敏感信息
- 硬编码的内部地址

**需要保留的**：
- 所有功能代码（包括之前的高级功能）
- 完整的前端 + 后端
- 数据库结构
- 配置文档

### 4.3 现有捐助用户处理

给 100 个赞助用户免费升级 v3.0 一年：

```
致 v2.0 早期赞助者：

感谢你在项目早期给予的支持！你的赞助是项目走到今天的重要动力。

作为回馈，你将获得：
- v3.0 Pro 个人版 1 年免费授权（价值 ¥299）

## 六、人才培养路径

### 6.1 四级晋升体系

```
Level 1：社区用户
  │  提 Issue、测试反馈
  ↓  签署 CLA，提交第一个 PR
Level 2：贡献者（Contributor）
  │  在 v2.0 开源版上贡献
  │  合并 1+ PR → v3.0 授权 3 个月
  │  合并 3+ PR → v3.0 授权 1 年
  ↓  持续贡献 3 个月，质量稳定
Level 3：核心贡献者（Core Contributor）
  │  签 NDA，获得 v3.0 私有仓库访问权限
  │  参与 v3.0 开发
  │  永久授权 + 收入分成（5-10%）
  ↓  合作 6 个月以上，贡献突出
Level 4：团队成员（Team Member）
  │  参与 v3.0 核心开发 + 架构决策
  │  收入分成（10-20%）
  │  可作为项目对外代表
```

**核心原则**：先在 v2.0 开源版上合作，表现好的再吸收到 v3.0 开发团队。

### 6.2 考察维度（Level 2 → Level 3）

| 维度 | 考察点 | 达标标准 |
|------|--------|---------|
| 代码质量 | PR 是否需要反复修改 | 多数 PR 一次通过或小修 |
| 技术能力 | 是否能独立解决复杂问题 | 至少 1 个中等难度 Issue |
| 持续性 | 是否稳定投入 | 3 个月内至少 5 个合并 PR |
| 沟通协作 | Issue/PR 讨论是否专业 | 有效沟通，不情绪化 |

### 6.3 权限分级

```
Level 2（v2.0 贡献者）：
  ✅ v2.0 开源仓库写权限（PR 审核后合并）
  ✅ v3.0 个人版授权
  ❌ v3.0 私有仓库访问
  ❌ 商业机密信息

Level 3（核心贡献者）：
  ✅ v2.0 开源仓库写权限
  ✅ v3.0 私有仓库读权限（指定模块）
  ✅ v3.0 永久授权
  ✅ 参与 v3.0 开发讨论
  ❌ v3.0 核心算法访问
  ❌ 客户信息 / 商业数据

Level 4（团队成员）：
  ✅ v3.0 私有仓库完整访问
  ✅ 参与架构决策
  ✅ 收入分成
  ✅ 代表项目对外沟通
```

### 6.4 v2.0 → v3.0 过渡流程

1. **邀请**（你主动发起）→ 发送 NDA
2. **签 NDA + 授予权限** → 获得 v3.0 指定模块访问权限
3. **考察期**（1-2 个月）→ 在 v3.0 上提交 PR
4. **正式确认** → 约定收入分成比例

### 6.5 任务分配

| 层级 | 任务类型 |
|------|---------|
| Level 2（v2.0） | Bug 修复、数据源适配、文档完善、工具函数优化、UI 小改进 |
| Level 3+（v3.0） | 新功能开发、性能优化、架构改进、客户定制需求 |
| 你自己 | 核心算法、商业逻辑、架构设计、发布决策、客户沟通 |

### 6.6 收入分成机制

采用"项目奖金"而非"股份"：

```
v3.0 每季度收入分配：
  - 30% → 项目所有者
  - 35% → 团队奖金池（按贡献分配）
  - 17.5% → 开源社区基金（ bounty、服务器费用）
  - 17.5% → 再投资（营销、法务、工具）

贡献点数：
  - 每个 PR +1 点
  - 每个 bug 修复 +0.5 点
  - 重大功能 +5 点
  - 季度末按点数比例分配
```

## 十一、核心原则总结

1. **逐步开源**：旧版本开源引流，新版本付费变现
2. **全部开源**：开源版功能完整，不用"半开源"损害声誉
3. **授权而非赞助**：从"自愿付费"转向"使用即付费"
4. **用旧价值换新流量**：v2.0 高级功能开源 = 免费营销
5. **先合作再信任**：v2.0 贡献 → 筛选 → v3.0 核心团队
6. **用机制而非感情**：明确的标准和流程，避免人际纠纷
7. **持续更新是核心竞争力**：让正版比盗版更划算
8. **合规是底线**：工具定位 + 免责声明 + 律师背书
