# AI 股票分析做了三代，我们终于想清楚一件事

---

## 先说说这件事的难点

用 AI 做股票分析，跟用 AI 聊天、写文案、画图，本质不是一回事。

**难点一：AI 是概率模型，但股票分析要求稳定可靠**  
ChatGPT 今天写的文案跟明天不一样，没关系。但股票分析不行——今天问"茅台怎么样"，明天再问同样的问题，输出格式变了、数据变了、结论也变了，你根本没法信。

**难点二：数据要求极高**  
AI 可以编故事，但不能编数据。"某公司 ROE 18.5%"这句话，18.5 是对的还是编的？如果有三个数据源，口径都不一样，听谁的？这些问题不解决，分析全是空中楼阁。

**难点三：容错成本极高，出了错代价很大**  
AI 写文案写错了，改改就行。股票分析看错了，可能就是真金白银的损失。正因如此，后面四个难点才必须解决--不是"锦上添花"，是"不得不做"。

**难点四：不能是黑盒**  
AI 说"看好"，你得知道它看了什么数据、怎么推理的、为什么这么判断。黑盒式的输出，没人敢拿来做投资决策。

**难点五：经验要能累积**  
这次漏看了"股东减持公告"，下次还要漏吗？AI 要能从失败里学习，不能每次都从零开始。

正因为有这五个难点，所以市面上绝大多数 AI 股票分析工具，用起来都像在开盲盒。

---

## 起点：踩了一年多的坑

去年刚开始做的时候，我们跟所有技术团队一样，觉得"多个 AI 分工协作"就能解决股票分析的问题——一个看市场、一个看新闻、一个看基本面，汇总成报告。

听起来很合理。跑通了，能出报告了。但很快我们就发现：

**AI 出的报告，像在开盲盒。**

今天问"茅台怎么样"，它给你一段分析。明天问同样的问题，格式全变了。后天它编了个数据，基于这个编造的数据写了一整段看似严密的分析，你读起来很流畅，完全看不出哪里是幻觉。

这不行。股票分析不是聊天，看错一次就是真金白银的损失。

从那之后，我们迭代了三代系统，核心只解决一个问题：

> **怎么让 AI 的输出从"开盲盒"变成"可信赖的工具"？**

这篇文章是我们的踩坑史。每一代踩了什么坑、怎么填的、填完发现什么新坑。现在的 3.0 做到了什么程度，哪些还没做到。

---

## 第一代：能跑了，但 AI 像在"开盲盒"

最早的版本是 v0.1.x 系列，用 Streamlit 做的单页应用。

思路很直接：让多个 AI 分工--市场分析师、新闻分析师、基本面分析师、风险经理，各司其职，汇总成报告。跑通了，能出报告了。

**但用了几次就发现不对劲。**

### AI 会编数据，你还看不出来

这是最要命的问题。AI 说"某公司 ROE 18.5%"，可能是对的，也可能是它获取不到数据时自己"生成"出来的。更麻烦的是，基于这个编造的数字，它会继续推理，写出一整段看起来很严密的分析。

你读起来很流畅，完全看不出哪里是幻觉。数据是编的，结论是基于编的数据推出来的，但整段分析读起来头头是道。

### 出问题了不知道哪错了

报告里有个数据不对，你去翻系统日志。日志是有的，但乱成一团--各种 Agent 的输出混在一起，没有结构，没有关联。只有程序员才看得懂，普通用户根本无从下手。

它看了什么数据、怎么推理的、为什么得出这个结论--你得在一堆日志里自己拼凑。AI 像个黑盒，错了就是错了，查问题全靠扒日志。

### 输出格式不稳定

提示词能一定程度约束输出格式，但不稳定。今天让它输出"投资倾向：乐观"，它给了。明天同样的问题，它输出"我们认为这只股票值得看好"。

一个 Agent 输出格式变了，下游所有 Agent 跟着乱，最后报告里出现一堆对不上的内容。

### AI 犯过的错，下次还犯

这次分析茅台，AI 编了个 ROE 数据。你发现了，跟它说"下次别编"。下次分析五粮液，它照样编。

系统没有记忆。每次分析都从零开始。

**第一代的价值**：验证了"多个 AI 协作出报告"这条路走得通。

**第一代的问题**：数据不可信、出错不可查、输出不可控、经验不累积。

---

## 第二代：功能更多了，但核心问题没解决

2.0 版的时候，我们加了很多实用功能：

- **复盘分析**：把历史交易记录导入系统，让 AI 做交易复盘，总结盈亏原因
- **持仓分析**：对用户当前持仓做整体风险评估、行业集中度分析
- **交易计划**：辅助制定交易计划，明确买入、止损、止盈的条件
- **提示词自定义**：开放了每个 agent 的 system prompt，用户可以根据自己的风格调

功能更全了，用户选择更多了。

**但核心问题还在。**

不管加了多少功能，每个 Agent 的输出质量，还是靠 Prompt 里"说好"。LLM 是概率模型，你跟它说好输出 JSON，它今天给了，明天可能给你一段散文。用户自定义了提示词，输出更不可控了。

我们加了很多功能，但每个功能的输出质量都没有底层保障。**不是功能不够多的问题，是质量治理的问题。**

### 用户也试过别的工具，遇到同样的问题

很多用户在群里聊过，上半年用小龙虾（OpenClaw）搭过股票分析。

小龙虾的思路是"给 AI 更多自由"--让它自己调 API、写代码、操作文件。听起来比我们的流程更强大。

但实际用起来，问题更严重了：

- **数据抓取不稳定**：AI 自己去网上抓数据，接口限流、抓不到、格式乱
- **报告出错没人管**：AI 输出有问题，你去查日志，还是只有一行"Agent 执行完成"
- **经验不累积**：这次犯的错，下次照犯
- **格式完全不可控**：今天输出表格，明天输出散文，后天不知道输出什么
- **Token 消耗大**：自主 Agent 会循环调用，一个简单任务走几十步，Token 烧得很厉害

这些工具各有各的优势，但在股票分析这个场景里，都遇到了同一个问题：**AI 的输出不受控**。

---

## 踩坑后的反思

2.0 做完之后，我们停下来想了一阵子。

问题到底出在哪？

不是 Agent 不够多。不是流程不够复杂。不是模型不够聪明。

**问题是：我们一直在"让 AI 做更多事"，但没有"让 AI 做的每件事都更可靠"。**

投资研究是容错成本极高的场景。看错一次，可能就是真金白银的损失。在这种场景里，"可靠"比"聪明"重要一万倍。

我们列了一份清单，这六条就是 3.0 要解决的事：

1. AI 的输出格式必须稳定，不能每次都不一样
2. AI 不能编数据，编了也要被当场抓住
3. 出问题要能查，不能是黑盒
4. 格式层面的错误要能记住，下次自动拦截
5. 用户要有能力扩展，但扩展不能失控
6. 数据来源要专业，不能靠 AI 自己网上找

---

## 第三代：把 AI 关进笼子，同时给它最好的工具

3.0 的核心理念变了：

> **不是让 AI 更聪明，而是让 AI 更可控。**

在讲具体能力之前，先说我们这一代守住的三个原则：

**AI 做研究辅助，决策永远在人**。系统不会帮用户下单，AI 给你的是"这件事的乐观/审慎/中性判断 + 依据"，看完你自己判断。我们认为这是对用户负责的方式。

**不承诺收益**。系统最多提高"长期少犯错"的概率，不能变成印钞机，也从来不这么承诺。

**先打基础，再扩功能**。3.0 这一代，我们把重心放在基础设施上--格式校验、执行轨迹、断言规则、数据口径统一、Agent 工坊、Skill 工坊。这些不是花哨的功能，但它们是底座。

在这个底座上扩展功能和应用很方便：加一个新分析师，走 Agent 工坊，6 步上线；加一个新工具，走 Skill 工坊，6 步验证。而且扩展出来的流程都受控--有格式校验、有执行轨迹、有断言保护。

我们做了两件事：**让 AI 受控地分析**，和**让能力受控地扩展**。一件一件说。

### 一、AI 出的报告，每次格式都一样

你问"茅台怎么样"，AI 给你的报告每次都长这样：

- **投资倾向**：乐观 / 审慎 / 中性（只能是这三个词之一）
- **把握程度**：0-100 的数字（不能是"比较高"这种模糊话）
- **核心理由**：一段不少于 50 字的文字（不能是空白）

不管你问多少次，不管哪只股票，格式都固定。

**怎么做到的**：不是"跟 AI 说好输出什么格式"--LLM 是概率模型，说好了也可能变。我们在代码里定义死了输出必须包含什么字段、每个字段允许什么值。AI 输出之后，代码立刻校验。不通过就标记为"校验失败"，不会让错误悄悄流入下游。

**举个直白的例子**：

你问 AI"茅台现在能买吗"。

以前的回答可能是："茅台基本面强劲，我们对后市持乐观态度，建议重点关注。"——听起来没问题，但你不知道这个结论是怎么来的，下次问可能又变了一个说法。

现在的回答是：

> **投资倾向**：审慎
> **把握程度**：65
> **核心理由**：茅台一季度营收同比增长 15%，但高端白酒消费场景恢复不及预期，批价边际走弱，库存周转放缓。短期估值处于历史中位数附近，缺乏明确催化。

同样的分析能力，但输出受控、可追溯。你看到的是明确的判断和依据，每次格式都一样。

### 二、AI 错了，你能查到

报告里哪个数据不对，你可以在任务中心点"执行轨迹"，打开后能看到每个 Agent 的完整执行过程：

- 这个 Agent 输入了什么（哪些分析师的结论、什么股票、什么时间）
- Prompt 全文是什么（完整的 system prompt 和 user prompt，一字不差）
- AI 原始返回是什么（LLM 给出的完整原文，不是截断的摘要）
- 解析成了什么结构（哪些字段、解析是否成功）
- 校验为什么没通过（具体哪个字段出了问题）
- 这次调用花了多少 Token、耗时多久

**怎么做到的**：系统把每次 Agent 执行的"输入、Prompt、LLM 返回、解析结果、校验状态、Token 用量"全量记录下来，叫"执行轨迹"。覆盖所有 Agent——内置分析师、研究经理、风险经理、交易员，以及你在 Agent 工坊里自己创建的分析师。

**默认关闭，按需开启**：执行轨迹记录的是 Prompt 全文和 LLM 原始返回，数据量不小。所以默认关闭，不日常记录。两种方式开启：
- 排查具体问题时，发起分析时勾选"记录执行轨迹"（只对这次分析生效）
- 或在系统设置里全局打开（所有分析都记录，90 天后自动清理）

出问题后，从发现问题到定位问题，从几小时缩短到几分钟。AI 不是黑盒，是玻璃盒。

### 三、格式层面的错误，踩过一次，下次自动拦截

AI 输出了违规术语、缺了必填字段、枚举值越界--这些**格式层面**的错误，可以从执行轨迹里找到，提炼成一条断言规则。下次任何 Agent 输出类似内容，自动拦截。

比如 AI 这次输出了"建议买入"这种违规术语，你提炼成一条断言规则。下次任何 Agent 再输出"建议买入"，当场拦下。

**怎么做到的**：我们把格式层面的错误提炼成 7 种类型的"断言规则"--禁用术语、必填字段、枚举值、数值范围、格式匹配、必备章节等。

这些规则是热插拔的：数据库里启用/关闭，不用改代码、不用重启服务。系统用得越久，积累的规则越多，格式层面的错误越少。

需要说明的是：**内容层面的经验**（比如这次分析漏看了某个角度），系统会沉淀到记忆层供后续分析参考，但这是"参考"不是"强制"。格式能强制，内容只能引导。这也是我们后续要继续打磨的方向。

我们认为，比起让 AI 假装全能，承认边界更负责。

### 四、你能加自己的分析师

你有自己的分析需求？比如"我想要一个专门看新能源产业链的分析师，重点关注锂矿和正极材料"。

跟系统说一声，它帮你做一个：

1. 聊需求：系统问你"看什么赛道、关注什么指标、输出什么格式"
2. 确认方案：生成规格说明书，你确认
3. 能力盘点：系统检查现有工具能不能覆盖你的需求，能复用的不重复造
4. 自动生成：生成 Agent 代码
5. 真数据测试：用真实股票跑一遍，不是模拟数据
6. 发布上线：测试通过后发布，不用重启服务

上线后，这个新分析师跟内置的一样：报告格式固定、出错能查、犯了错系统记住。

**关键点**：扩展不意味着失控。自定义 Agent 同样受格式约束、同样写入执行轨迹、同样受断言保护。更妙的是--某个人创建的 Agent 犯了错，这条错误变成一条断言，保护了所有人。一个人的教训，变成全系统的防护。

### 五、AI 用的数据是专业的、口径统一的

AI 给你的"某公司营收 100 亿"，是真的 100 亿，不是它编的。

我们接入了 **Tushare、QMT、AkShare** 这些专业数据源。AI 不是自己去网上抓数据，是通过统一的数据适配器从专业机构拿数据。

凭证加密存储，启动时自动恢复。

更重要的是，**我们对所有数据源的口径做了统一**。不同数据源可能有不同的字段名、不同的计算口径，我们在系统里做了统一的标准化处理，保证所有分析师拿到的数据是一致的、可比的。

同时，系统也支持通过 MCP 协议接入外部数据源和工具，方便用户扩展自己的数据渠道。

**为什么要接入专业数据源并做口径统一**：股票分析的本质是"基于真实数据的推理"。如果数据来源不可靠、口径不一致，推理再漂亮也是空中楼阁。AI 自己去网上抓数据，接口限流、抓不到、格式乱、真假难辨，这些问题我们都踩过坑。现在的做法是：数据必须来自专业机构、口径必须统一、AI 只负责分析。

### 三代能力对比表

| 能力 | 第一代（v0.1.x） | 第二代（v2.x） | 第三代（v3.0） |
|------|------------------|--------------|--------------|
| **输出格式稳定** | 靠 Prompt 约束，不稳定 | 同上 | Schema 契约强制校验，每次都一样 |
| **数据可信** | AI 可能编数据 | 同上 | 接入专业数据源 + 口径统一 + 校验拦截 |
| **出错可查** | 有日志但混乱，只有程序员看得懂 | 同上 | 全量执行轨迹，精确到字段（默认关闭，按需开启） |
| **经验累积** | 无 | 无 | 格式层强制 / 内容层参考 |
| **能力扩展** | 写代码 | 写代码 + 提示词自定义 | 对话式创建 Agent/Skill，真数据测试，受控扩展 |
| **企业级功能** | 单页应用，设置管理 | 持仓分析、复盘分析、交易计划 | 统一 AI 助手入口、自然语言选股、自主规划分析、自定义Agent和skill |

## 我们的三个原则

**AI 做研究辅助，决策永远在人**。系统不会帮用户下单，AI 给你的是"这件事的乐观/审慎/中性判断 + 依据"，看完你自己判断。我们认为这是对用户负责的方式。

**不承诺收益**。系统最多提高"长期少犯错"的概率，不能变成印钞机，也从来不这么承诺。

**先打基础，再扩功能**。3.0 这一代，我们把重心放在基础设施上--格式校验、执行轨迹、断言规则、数据口径统一、Agent 工坊、Skill 工坊。这些不是花哨的功能，但它们是底座。

在这个底座上扩展功能和应用很方便：加一个新分析师，走 Agent 工坊，6 步上线；加一个新工具，走 Skill 工坊，6 步验证。而且扩展出来的流程都受控--有格式校验、有执行轨迹、有断言保护。

底座打好了，后面扩展具体的功能和应用，是自然而然的事。

## 写在最后

从第一代到第三代，一年多下来，我们最大的认知转变是：

> **不是让 AI 做更多事，而是让 AI 做的每件事都更可靠。**

1.0 的时候，我们觉得"AI 能出报告就行"。

2.0 的时候，我们觉得"流程更复杂、Agent 更多就行"。

3.0 的时候，我们想清楚了：**股票分析需要的不是无拘无束的 AI，是在规范框架内可控的自由 AI**。

"自由"和"可控"不是矛盾的。我们的系统里，你可以自由地构建新的 agent、新的流程、新的 skill，但都在规范内——都有明确的校验规则、都写入执行轨迹、都受断言保护、都可以验证。

AI 有它擅长的天赋：理解语言、抓住重点、串联信息。我们要做的不是抹掉这些天赋，而是让天赋在规则内发挥。

3.0 不是终点。断言库会越积越丰富，自定义 Agent 会越来越多，数据源会越来越全。系统会越用越可靠。

**这条路还长，但方向是对的。**
