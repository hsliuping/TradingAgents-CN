# TradingAgents-CN Pro v3.0.0-beta.4 更新说明

发布日期：2026-07-10
版本定位：**多智能体平台化升级（第四个测试版）** — 在 beta.1 基础上补齐能力索引管理面板、Docker 部署链路、NSIS 安装体验与 Skill 工坊质量增强，配合 Python 3.11.9 运行时与分层文档体系，形成可对外测试的完整版本。

## 一、版本亮点

1. **能力索引管理面板（新功能）**：在系统管理中新增「工具能力索引」面板，支持 Embedding 预检查、手动重建索引、状态可视化，让 Skill 生成与 Agent 工坊的语义检索能力可见、可控、可恢复。
2. **Docker 部署链路打通**：基于 `docker-compose.compiled.yml` + Nginx 反向代理统一入口，默认拉取 `3-latest` 标签镜像，支持 ARM64，提供 Linux/macOS/Windows 一键部署脚本。
3. **NSIS 安装脚本全面优化**：全中文界面、端口冲突检测、安装路径中文/空格校验、动态查找 MongoDB 版本目录、VC++ Runtime 直接复制，安装体验显著提升。
4. **Python 运行时升级**：嵌入式 Python 从 3.10.11 升级到 3.11.9，享受性能改进与安全更新，同时保持对核心依赖的兼容性。
5. **Skill 工坊质量增强**：新增财经专家判断模块（`financial_expert_advisor`）与 helper 数据源标签系统（`data_source_handling`），提升 Skill 生成在「无数据」场景下的判断质量。
6. **文档目录重组**：按编号分层管理（`01-product` ~ `99-archive`），强制版本号目录，禁止相对命名，文档体系更清晰、可追溯。

## 二、本次 beta.4 主要更新

### 1) 能力索引管理面板（新功能）

本次新增的能力索引管理面板位于「设置 → 系统管理 → 工具能力索引」，是 v3.0 能力索引服务（`CapabilityIndexService`）的可视化入口。

1. **Embedding 预检查**：在构建索引前，先测试首个 embedding 调用是否成功，若 API Key 无效或网络不通，快速跳过避免长时间超时，返回 `skipped_embedding_unavailable` 状态。
2. **手动重建索引**：提供「强制重建」按钮，调用 `POST /api/capability-index/rebuild`，全量删除并重新构建向量索引。
3. **状态可视化**：展示当前索引的 `sync_mode`、`total_documents`、`indexed_documents`、`skipped_documents`、`vector_backend`、`fingerprint` 等关键字段。
4. **增量同步**：默认通过指纹（fingerprint）比对，仅在工具/Skill 集合变更时触发增量同步，避免重复构建。
5. **关键词回退**：当 embedding 不可用时，自动回退到关键词匹配，系统正常运行不阻塞。
6. **预构建索引分发**：提供 `scripts/build_capability_index.py` 脚本，发布前用 DashScope embedding 构建全量工具索引，写入 `data/chromadb/` 随安装包分发，让未配置 embedding 的用户也能使用语义搜索。

### 2) Docker 部署支持

1. **`3-latest` 标签策略**：Docker Hub 镜像使用 `3-latest` 作为 v3.x 系列的滚动标签，替代裸 `latest`；精确版本标签（如 `3.0.0-beta.4`）不可变，永不覆盖。可通过 `IMAGE_TAG` 环境变量锁定版本。
2. **Nginx 反向代理统一入口**：前后端通过 Nginx 同一端口（默认 8082）访问，无跨域问题；`resolver 127.0.0.11 valid=10s` 解决容器更新后 DNS 解析问题。
3. **编译版镜像**：后端使用编译后的 `.pyc` 与 `.pyd` 文件，代码保护更强；前端为构建后的静态资源。
4. **一键部署脚本**：提供 `deploy.sh`（Linux/macOS）和 `deploy.ps1`（Windows），交互式配置端口、自动下载配置文件、创建目录、启动服务。
5. **ARM64 支持**：提供 `docker-compose.hub.nginx.arm.yml`，显式指定 `platform: linux/arm64`，支持树莓派、Apple Silicon 等 ARM 设备。
6. **开发环境隔离**：`docker-compose.dev-compiled.yml` 提供独立端口（Nginx 8092、MongoDB 27018、Redis 6380），与生产环境互不干扰。

### 3) NSIS 安装脚本优化

1. **全中文界面**：`!insertmacro MUI_LANGUAGE "SimpChinese"` + `Unicode true`，安装向导全中文显示。
2. **端口冲突检测**：使用 `netstat -ano -p tcp | findstr /C:":$端口 " | findstr LISTENING` 检测端口占用，在安装阶段即提示用户调整。
3. **安装路径校验**：`ValidateInstallDirPath` 函数拒绝中文、空格、特殊字符路径，避免 MongoDB/Redis 路径问题；只允许英文字母、数字和 `._-` 字符。
4. **动态查找 MongoDB 版本目录**：不硬编码版本号，自动适配不同 MongoDB 版本。
5. **VC++ Runtime 直接复制**：直接复制 VC++ Runtime DLL，不安装 VC Redist，更稳定。
6. **简化安装模式**：支持「全新安装」与「升级安装」（保留配置和数据）两种模式。
7. **端口探测性能优化**：使用并行作业（`Start-Job`）探测所有端口，端口检测时间从 ~4 秒降低到 ~1 秒。

### 4) Python 运行时升级

1. **版本升级**：嵌入式 Python 从 3.10.11 升级到 3.11.9（3.11 系列最后一个提供嵌入包的版本）。
2. **性能改进**：Python 3.11 相比 3.10 启动时间更快、异常处理更高效、标准库多项优化。
3. **兼容性保障**：`pyproject.toml` 中 `requires-python = ">=3.10"`，核心依赖均已完成 3.11 兼容性验证。
4. **脚本统一**：`setup_embedded_python.ps1`、`build_portable_package.ps1`、`build_pro_package.ps1` 默认 `$PythonVersion = "3.11.9"`。

### 5) Skill 工坊增强

1. **财经专家判断模块**（`core/tools/external/financial_expert_advisor.py`）：当 helper 返回 `no_data` 时，用 LLM 作为资深金融从业者判断该情况是否业务合理（如银行股无质押是合理的，民营股无质押可能不合理），给出专家建议并推荐更合适的测试股票。
2. **helper 数据源标签系统**（`ImplementationHelper.data_source_handling`）：
   - `self_contained`：helper 自包含，内部已封装数据源调用，LLM 直接调用即可。
   - `local_only`：helper 只查本地 MongoDB，若本地无数据 LLM 可能需要自己调外部数据源补充。
   - `partial`：helper 覆盖部分需求，LLM 可能需要补充其它数据源或计算。
3. **判断结果反馈**：专家判断结果以 `ExpertJudgment` 结构化输出，`is_rational` / `reasoning` / `recommended_stocks` / `advice` / `confidence` 字段，反馈给 Skill 生成管道指导后续迭代。

### 6) 文档目录重组

1. **按编号分层管理**：
   - `01-product/`：产品定位、发布说明、版本对比
   - `02-user-guide/`：用户指南
   - `03-development/`：开发文档
   - `04-operations/`：运维文档
   - `05-design/`：设计文档（按版本号目录，如 `v3.0/`、`v4.0/`）
   - `06-knowledge/`：知识沉淀（跨版本积累）
   - `07-courses/`：高级交易课程
   - `08-blog/`：技术博客
   - `99-archive/`：归档区（按版本号目录）
2. **版本号管理规则（强制）**：`05-design/` 和 `99-archive/` 必须使用明确版本号目录，禁止 `current`、`latest`、`new`、`next`、`future` 等相对概念命名。
3. **版本迭代流程**：发布新主版本时，`05-design/v3.0/` → `99-archive/v3.0/`，`05-design/v4.0/` 成为新的当前版本，新建 `05-design/v5.0/`。
4. **文档命名规范**：统一小写 kebab-case，版本相关文件加版本后缀，临时文件加日期前缀。

## 六、配置要求

### 1) Windows 配置要求

#### 最低要求
- **操作系统**：Windows 10 64 位（推荐 Windows 11）
- **内存**：4GB RAM
- **磁盘空间**：2GB 可用（安装程序约 350MB，完整运行约 2GB）
- **Python**：3.11.9（安装包内置嵌入式 Python，无需单独安装）
- **浏览器**：Chrome / Edge / Firefox 现代版本

#### 推荐配置
- **操作系统**：Windows 11 64 位
- **内存**：8GB+ RAM
- **磁盘空间**：10GB+ 可用（含数据存储）
- **CPU**：4 核+

#### 端口要求（默认）
| 服务 | 端口 |
|------|------|
| MongoDB | 27019 |
| Redis | 6381 |
| Backend API | 8002 |
| 前端（Nginx） | 8082 |

> 安装程序支持自定义端口，会检测端口冲突并提示调整。

### 2) Docker 配置要求

#### 前置要求

## 九、已知限制与问题

### 1) 测试版本限制
- v3.0.0-beta.4 为测试版本，不建议用于生产资金决策。
- 部分 v3.0 新功能（如完全自定义流程、更丰富的 MCP 生态）仍在持续完善。
- 建议先在测试环境验证核心流程后再部署到生产环境。

### 2) 功能限制
- **飞书/钉钉适配器**未实现，Gateway 当前仅支持 QQ Bot。
- **ETF 分析**产品层成熟度弱于普通股票主流程，工具与提示词仍需完善。
- **MCP 数据源类接入**（数据降级链扩展）为规划内容，尚未完全落地。
- **分层提示词架构**部分实现，五层完整组装需后续逐项对照补全。
- **task_progress 广播**当前发给所有 WebSocket 连接，生产环境应限定为任务所属用户。

### 3) 能力索引限制
- 能力索引的语义搜索依赖 embedding 模型，未配置时自动回退到关键词匹配。
- 预构建索引使用 DashScope `text-embedding-v3`（768 维），不同 embedding 模型的向量不可混用。
- 索引存储在 `data/chromadb/` 目录，磁盘占用约 2MB（255 个工具）。

### 4) Docker 部署限制
- 当前 `.pyd` 文件仅支持 Windows，Linux/macOS 下的 Cython 编译产物为 `.so` 文件，需单独编译。
- ARM64 平台部分依赖可能需要额外验证。

### 5) 升级注意事项
- 从 v3.0.0-beta.1 及更早版本升级时，建议先备份数据。
- 自定义提示词模板需要复核，v3.0 报告风格更偏向「研究辅助」。
- 数据库配置文件已更新，包含 v3.0 全部新集合的预配置数据。

## 十、升级建议

### 1) 升级前检查
1. 备份现有数据（MongoDB 导出、`.env` 文件、自定义配置）。
2. 确认端口可用（27019/6381/8002/8082）。
3. 准备至少一个 LLM API 密钥。
4. 如需使用能力索引语义搜索，准备 DashScope API 密钥。

### 2) 升级后验证
1. **智能助手主链路**：对话、工具调用、分析触发、报告查看。
2. **能力索引面板**：设置 → 系统管理 → 工具能力索引，查看状态，必要时手动重建。
3. **单股分析**：用熟悉的股票验证分析流程完整性。
4. **MCP Server**（如需）：在系统配置中创建 MCP API Key。
5. **QQ Bot**（如需）：配置 QQ 开放平台 AppID/Secret/Token。

### 3) 适合升级的用户
- 希望用自然语言完成复杂投资研究任务。
- 需要自定义 Agent 或扩展系统工具能力。
- 有接入外部数据源/MCP 的需求。
- 希望 Skill 迭代不破坏已有 Agent 绑定。
- 愿意尝试新功能，对测试版本有容忍度。

### 4) 建议保留 v2.1.x 的用户
- 当前工作流已稳定，不需要新功能。
- 团队/个人更习惯表单化操作。
- 对测试版本稳定性有顾虑。
- 主要用于生产环境，不愿承担测试版本风险。
