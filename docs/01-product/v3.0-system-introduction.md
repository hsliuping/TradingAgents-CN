# TradingAgents-CN v3.0：让 LLM 受控地分析，让用户灵活地扩展

> **我们不是把 AI 做得更聪明，而是把 AI 做得更可靠。**

通用大模型做股票分析，最大的问题不是"不够聪明"，而是**你不知道它什么时候在编造**。TradingAgents-CN v3.0 解决两个核心问题：

1. **怎么让 LLM 受控地分析股票** -- 不是信口开河，而是按规格输出、可校验、可追溯、可纠错
2. **怎么提供灵活受控的扩展** -- 不局限于内置 Agent，用户能自定义 Agent、流程和 Skill，但扩展不失控

这两条主线贯穿 v3.0 的全部设计。

---

## 一、痛点：现有方案为什么不行

### 通用大模型直接做股票分析

- 问它财务数据，它可能生成一段看起来合理但实际不存在的数字
- 让它输出 JSON，它可能输出一段格式差不多的 Markdown
- 同一个问题问两次，给出两种不同结论，而且都说得头头是道
- 你不知道它什么时候在编造

### 低代码平台（Dify / Coze / n8n）搭的 Loop 系统

- **Prompt 漂移**：这次输出"乐观/审慎/中性"，下次变成"看涨/看跌"，平台不强制校验
- **格式随机**：JSON 这次对了，下次多一个字段少一个字段，下游解析崩了
- **错误不可追溯**：某个 Agent 输出有问题，回去看日志只有一行"执行完成"
- **经验不可累积**：这次发现好的分析角度，换一只股票全忘了
- **合规裸奔**：可能输出"建议买入""目标价 XX"--投资领域的合规红线

### 开源框架（AutoGen / CrewAI / 原版 TradingAgents）

- 框架解决了"怎么通信"，没解决"怎么可靠"
- LLM 仍然自由发挥，没有 Schema 约束
- 没有合规校验、没有执行轨迹、没有记忆层、没有断言机制
- 同一个错误反复犯，系统不会越用越好

## 二、第一主线：让 LLM 受控地分析股票

### 核心思路：不让 LLM 自由决策，让它按规格翻译

借鉴桥水 Pat 的"规格驱动"思路：用 Pydantic 模型预定义输出 schema，在 system prompt 最前面注入格式要求。LLM 的工作从"自由决策输出什么"降级为"翻译这份预定义 schema"。

**关键原则**：校验不是"LLM 自己决定要不要检查"。校验是写在架构里的、强制的 Python 代码。一个智能体可能会"忘记"做检查，但一条固定的校验管线不会。

### 分析流程：全链路受控

v3.0 的标准股票分析流程，每个环节都有质量保障：

```
分析师群（8 个）          研究辩论                管理者综合研判
market / news /          bull vs bear            research_manager
fundamentals / social    乐观 vs 审慎             risk_manager
sector / index / etf     交替发言                schema 契约校验
chip_distribution         辩论计数控制             断言自动执行
    │                       │                       │
    ▼                       ▼                       ▼
工具调用摘要传递          辩论反思自动提炼          执行轨迹全量记录
（下游可见上游数据获取）   （debate_lesson 入 mem0） （输入/输出/校验/Token）
    │                       │                       │
    └───────────────────────┼───────────────────────┘
                            ▼
                    交易员生成用户简报
                    trader_v2
                    合规术语三层防护
                    简报结构契约校验
```

**分析师层**（8 个 Agent）：
- 每个分析师有标准化工具调用循环：LLM 绑定工具 -> 执行 tool_calls -> 再次调用 LLM 生成报告
- 工具调用摘要传递：前序 Agent 的数据获取过程对下游透明，下游能看到"用了什么工具、传了什么参数、返回了什么结果"
- 指数退避重试：默认 3 次，应对 LLM 超时

**辩论层**：
- DEBATE 节点控制流程，不是装饰。乐观研究员和审慎研究员通过条件边交替发言
- 路由函数检查辩论计数决定继续还是结束，支持运行时调整辩论深度
- 辩论结束后自动触发反思，提炼为结构化 `debate_lesson`

**管理者层**（核心受控点）：
- `ResearchManagerOutput` schema：必须包含 analysis_view、confidence、core_evidence 等
- `RiskAssessmentOutput` schema：包含 risk_score（0-1）、confidence（0-1）、research_summary（研究证据汇总）、key_evidence（核心证据清单）、info_gaps（信息缺口），所有数值字段必须有范围约束
- 校验失败 -> 显式标记 `validation_status=failed` + 错误详情，不静默吞掉

**交易员层**：
- **Markdown 简报结构契约**：6 个必备章节（研究观察 / 核心研究证据 / 关键风险 / 后续关注 / 信息缺口 / 免责声明）
- **合规术语扫描**：禁止"买入/卖出/加仓/减仓/清仓/目标价/止损价"等交易指令术语

### 质量治理闭环：P0 -> P1 -> P2，让同一个错误不犯两次

| 层级 | 做什么 | 效果 |
|------|--------|------|
| **P0 Schema 契约** | Pydantic 模型强制校验 Agent 输出 | LLM 从"自由发挥"降级为"按规格翻译" |
| **P1 执行轨迹** | 全量记录每次 Agent 执行的输入/输出/校验结果 | 出问题可回溯，不是黑盒 |
| **P2 可执行断言** | 工程师从失败轨迹提炼机器校验规则，后续自动执行 | 同一个坑踩过一次，第二次被拦截 |

**P2 的 7 种断言类型**：

| 类型 | 防什么 | 示例 |
|------|--------|------|
| `TERM_FORBIDDEN` | 禁用术语 | 输出不能出现"买入" |
| `FIELD_REQUIRED` | 必填字段缺失 | risk_manager 必须输出 confidence |
| `FIELD_ENUM` | 枚举值越界 | risk_level 只能是"低/中/高" |
| `FIELD_RANGE` | 数值越界 | confidence 必须在 0-1 之间 |
| `SCHEMA_MATCH` | 整体 schema 不匹配 | 输出必须符合 RiskAssessmentOutput |
| `REGEX_MATCH` | 格式不合规 | ticker 必须是 6 位数字 |
| `SECTION_REQUIRED` | 章节缺失 | trader 必须包含"一句话结论" |

断言是**热插拔**的：数据库里 enable/disable，不改代码。**规则由工程师从失败轨迹手动提炼**——AI 自己不会挖掘规则，但人会根据真实事故把"踩过的坑"沉淀成可执行断言。命中计数自动累积，能看到哪些规则被触发最多。

**闭环流转**：P0 校验失败 -> P1 轨迹记录失败模式 -> 工程师从失败案例提炼成 P2 断言 -> P2 自动执行 -> 违规降级 -> 触发 P0 重新校验。系统越用越可靠，不是每次从零开始。

### 合规三层防护：让 AI 不踩红线

| 层级 | 机制 | 防什么 |
|------|------|--------|
| **Prompt 级** | system prompt 最前面注入合规要求 | 禁止交易指令术语、禁止目标价 |
| **Schema 级** | Pydantic 枚举约束 + 数值范围 | risk_level 只能是"低/中/高"，confidence 必须在 0-1 之间 |
| **后处理级** | `compliance.py`（1300+ 行）正则 + sanitize | 兜底过滤买卖指令、止损价等 |

LLM 这次听话不代表下次也听话。三层防护确保即使跑偏了，输出也不会带出违规内容。

### 复盘流程：受控的反思

v3.0 的复盘不是"写个总结"，是结构化的归因分析：

5 个复盘 Agent 各管一摊：
- **时机复盘**（timing）：评估交易时机选择的合理性
- **仓位复盘**（position）：评估仓位控制的合理性
- **情绪复盘**（emotion）：评估决策是否受情绪干扰
- **归因复盘**（attribution）：分析收益来源与可复制性
- **复盘整合员**（review_manager）：综合归因观察

复盘完成后自动触发**复盘反思**（trade_lesson），提炼"时机/仓位/情绪/归因"的教训，写入 mem0。下次分析时，Agent 可以引用之前的复盘经验。

### 反思机制：让经验自动沉淀

3 种反思场景自动触发，非阻塞设计：

| 场景 | 触发时机 | 产出 |
|------|---------|------|
| **分析反思** | 研究员报告生成后 | analysis_lesson（分析哪里做得好、哪里有改进空间） |
| **辩论反思** | 辩论结束后 | debate_lesson（正反方论点、裁决依据、可复用框架） |
| **复盘反思** | 交易复盘完成后 | trade_lesson（时机/仓位/情绪/归因教训） |

所有反思使用统一的 4 维度框架（Reasoning / Improvement / Summary / Query），输出严格 JSON，写入 mem0 的 `AGENT_EXPERIENCE` scope。超时 30 秒降级为原文写入，任何异常都不影响主流程。

### 执行轨迹：让每次 Agent 执行可回溯

`AgentExecutionTrace` 全量记录：输入了什么、LLM 返回了什么、解析成什么、校验是否通过、Token 用量多少。

- **渐进式采集**：record_inputs -> record_prompts -> record_llm_response -> record_parsed_output -> finish
- **非阻塞**：四层 try/except 保障，轨迹采集绝不影响 Agent 主流程
- **只存摘要**：output_raw_preview 存前 500 字符，避免数据库膨胀

出问题不再是黑盒。你可以回溯到具体某个 Agent，看它的输入、LLM 原始返回、解析结果、校验错误，精确定位跑偏点。

## 三、第二主线：灵活受控的扩展

### 核心思路：扩展能力可以自由增长，但每一步扩展都受控

v3.0 不把用户局限在 25 个内置 Agent 里。用户可以自定义 Agent、自定义工作流、自定义 Skill，甚至接入外部数据源。但所有扩展都经过验证和约束，不会"扩展着扩展着就失控了"。

### Agent 工坊：对话式创建自定义 Agent

7 阶段标准化流程（4→6 反复循环直到通过）：

```
需求探索 -> 需求确认 -> 能力盘点 -> 方案选择
                                          ↓
                                ┌─── 实现 ───┐
                                ↓            ↓
                          真数据测试  ←→  评估迭代
                                ↓            │
                              通过 ──────────┘
                                ↓
                             发布
```

**受控点**：
- **能力盘点**：向量搜索（Qdrant）+ 覆盖率评分，创建前就知道这个 Agent 能不能覆盖用户需求
- **真数据测试**：不是模拟数据跑通就行，用真实股票数据验证
- **多维度评估**：工具调用 / 输出覆盖 / 推理质量 / 数值可追溯性 / 约束控制 / 项目记忆绑定，6 维度评分 < 7 自动带反馈重跑
- **版本管理**：draft / testing / active 多状态，支持回滚
- **数据库驱动**：UniversalAgent 从 MongoDB `agent_configs` 加载，添加新 Agent 不需要改代码、不需要重启

### Skill 工坊：受控的代码生成（工程师配置式）

6 阶段生成管线：

```
需求分析 -> 侦察探测 -> 代码生成 -> 静态验证 -> 沙箱执行 -> 业务验收
```

**受控点**：
- **字段名防幻觉**：从 helper docstring 提取真实字段名注入 spec 生成提示词，避免 LLM 编造不存在的字段名
- **沙箱执行**：生成的代码先在沙箱跑一遍，跑通了才给用户
- **版本链管理**：`_v{N}` 后缀 + `parent_skill_id`，所有版本并行显示
- **旧版保护**：已绑定 Agent 的旧 Skill 不会被新版本覆盖，升级不破坏已有 Agent

### 自定义工作流：LangGraph 可视化编排

基于 LangGraph 的工作流引擎，支持：
- **可视化定义**：WorkflowDefinition 由节点和边组成，支持条件边、并行节点、合并节点
- **辩论机制**：DEBATE 节点控制辩论流程，条件边检查辩论计数
- **5 个内置模板**：标准股票分析、ETF 分析、交易复盘、持仓分析、空白自定义
- **动态 Agent 字段聚合**：`analyst_reports` 自动聚合上游报告

### MCP 生态：扩展外部能力

- MCP 服务器管理（创建/发现/启用/禁用）
- 凭证加密存储（Fernet 加密 + 列表页遮蔽）
- 启动自动恢复
- Skill 工坊通过 MCP 协议把外部工具接入系统，可接入 QMT、Wind、同花顺 iFinD 等外部能力

注意：核心行情数据来自 Tushare、QMT、AkShare 等专业数据源，通过统一适配器接入并做了口径统一，AI 不会自己网上抓数据。MCP 主要解决"已有专业数据源如何以工具形式被 Agent 调用"。

### LLM 适配层：10+ 供应商自由切换

| 供应商 | 特性 |
|--------|------|
| 阿里百炼（DashScope） | 通义千问系列，OpenAI 兼容接口 |
| Google AI | Gemini 系列 |
| DeepSeek | 支持 thinking 模式（R1/V4 reasoner） |
| 智谱 AI | GLM 系列 |
| OpenAI | GPT 系列 |
| 硅基流动 / OpenRouter / AIHubMix | 聚合平台 |
| Ollama | 本地模型，无需 API Key |
| 火山方舟 | 支持 reasoning_effort 推理深度控制 |
| Anthropic | Claude 系列 |

每模型独立配置 max_tokens / temperature / timeout / reasoning_effort，UI 设置即时生效。

### 记忆层：让扩展能力可累积

mem0 统一记忆层提供 7 种 MemoryScope：

| Scope | 让什么可累积 |
|-------|-------------|
| CONVERSATION | 对话记忆（滑动窗口） |
| USER_PREFERENCE | 用户偏好（投资风格、风险偏好） |
| ANALYSIS_INSIGHT | 分析洞见（跨次分析积累） |
| AGENT_EXPERIENCE | Agent 经验（辩论反思、分析教训） |
| SKILL_LESSON | 技能教训（Skill 生成失败模式） |
| TRADE_PATTERN | 交易模式（用户行为画像） |
| AGENT_BUILDER_LESSON | Agent 构建教训 |

自定义 Agent 的经验也会写入 mem0，跨次复用。系统越用越了解用户，不是每次从零开始。

## 四、两条主线如何交汇

两条主线不是独立的，它们在三个关键点交汇：

### 交汇点 1：自定义 Agent 同样受 Schema 约束

用户通过 Agent 工坊创建的自定义 Agent，如果担任管理者角色，同样需要定义 Pydantic schema、同样经过 P0 校验、同样写入 P1 执行轨迹、同样受 P2 断言约束。扩展不意味着失控。

### 交汇点 2：失败经验变成所有人的防护规则

某个自定义 Agent 输出了违规内容 -> P1 轨迹记录失败案例 -> 工程师从轨迹中提炼成 P2 断言 -> 下次任何 Agent（包括内置的）输出类似内容都会被拦截。一个人的教训变成全系统的防护。

### 交汇点 3：反思经验跨 Agent 复用

辩论反思提炼的 `debate_lesson`、分析反思提炼的 `analysis_lesson`，写入 mem0 后，自定义 Agent 也能检索引用。内置 Agent 的经验沉淀可以赋能自定义 Agent。

## 六、系统不能解决什么

1. **不能消灭未来的不确定性** -- 未来仍然不可知，系统最多让你更早看到变化、更快承认错误
2. **不能替代人的最终承担** -- 系统不能替你承担仓位、等待、波动、亏损
3. **不能自动发现所有未知未知** -- 系统可以通过反方、错误库、弱信号层去逼近，但不能彻底解决
4. **不能保证收益** -- 它最多只能提高"长期少犯错"的概率，不能变成印钞机

## 七、将要做哪些

### v4.0：让闭环真正转起来

v3.0 已经建成了基础设施，v4.0 的重点是让"判断 -> 记录 -> 时间 -> 反馈 -> 修正"这个闭环真正转起来：

- **长期跟踪闭环**：定时跟踪 -> 变化检测 -> 自动提醒 -> 复盘归因 -> 经验回流
- **研究资产沉淀**：将散落的分析结果、判断假设、错误教训结构化为用户的私有研究资产
- **旧版 Agent 彻底删除**：v3.0 已封堵全部入口，v4.0 清理代码
- **质量门禁强化**：分析师报告完整性检查、Skill 生成 HITL 修复、辩论结果回流

### v5.0：长期纠错系统

从第一性原理重新定义系统为"面向长期价值投资的、以减少错误为目标的认知操作系统"：

> **判断 -> 记录 -> 时间 -> 反馈 -> 修正**

这个闭环是系统成败的终极标准。v5.0 要让这个闭环真正转起来。

- **系统不是什么**：投资顾问 / 证券投资咨询机构 / 经纪商 / 任何投资建议的提供方
- **用户角色**：用户应将本系统视为"研究工具"，自行进行投资判断，投资决策的最终责任由用户承担
- **商业模式**：仅收取 Token 调用费、数据接口使用费及批量/定时等系统功能费，**不收取分析服务费或投资咨询费**
